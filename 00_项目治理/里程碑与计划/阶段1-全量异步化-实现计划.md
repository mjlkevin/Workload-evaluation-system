## 1. 目标与边界

**阶段 1 唯一目的**：让阶段 2 能够「只换实现、不动调用点」。全部 store accessor 与命令式守卫的签名从同步改为 async，函数体一字不改（仍走 JSON 文件）。验收 = 现有测试全绿、行为零变化。

**边界**：

- 只改签名不改实现；任何 store 切换到 PG 属阶段 2，本阶段禁止提前。
- `ops/config-integrity.ts` **不转换**（自带 `fs.readFileSync`、不经过 store accessor、启动期一次性路径），登记为阶段 2 删除对象（D15）。
- 不得修改任何测试断言；若某测试必须改断言才能通过，说明引入了行为变化，立即停止报架构侧。

## 4a. 技术债期限登记（2026-08-18 架构侧定级）

- **ISS-2026-08-18-003（CI test:modules 并发挂起，现以 `--test-concurrency=1` 串行绕行）**：期限 = **阶段 2 开工前必须完成根因定位**，给出结论（修复 / 确认串行为长期方案 + 理由）。若确认串行长期化，需同时给出 CI 时长增长预估与应对（分片、分 job 等）——阶段 2 依赖数据库的测试文件将从 17 个增至约 31 个，串行 + 数据库预计 CI 时长翻倍。责任人：阶段 2 开工者；登记于本文件与总看板问题池 ISS-2026-08-18-003。
- **ISS-2026-08-18-001（MSW 逃逸）**：提级为**前端问题池首位**；第二点（`onUnhandledRequest:'error'` 为何未拦下未匹配请求）优先于第一点（为何未 mock），因其直接决定前端门禁（CI `test-web` job）的实际强度。批 4 交付时附分诊结论。
- **ISS-2026-08-18-004（versions store 损坏文件静默当空库）**：`loadVersionsStore()` 的 `catch { return { records: [] } }` 模式使 JSON 损坏从可恢复变为不可恢复（下一次 save 把「空」落盘）。**阶段 1 不修**（修它属行为变化）；登记为**阶段 2 处理对象**——该 store 切换 PG 时此模式自然消失，但需确认新实现不重复此模式（读取失败必须显式报错，不得静默空库）。
- **批 4 跨批依赖点（特殊点 2）**：`versions.repository.ts` 的 `repairGlobalPlaceholderVersionCodes` 内调用 `loadVersionCodeRulesStore()`（system 域，**属批 5 范围**）。批 4 中它仍是同步函数，补 `await` 不改变行为；**批 5 执行时须确认该调用点不被遗漏**（批 5 把它改异步后，此处 `await` 才真正生效）。
