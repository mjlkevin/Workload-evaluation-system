| 描述 | 无样式、可访问性优先的 React 组件原语库，是构建高质量设计系统的基础设施（shadcn/ui 即构建于其上） |

### 核心亮点

1. **无样式原语 + 无障碍内建**：Dialog、Tooltip、Popover 等 30+ 组件只提供行为与无障碍语义（焦点陷阱、Escape 关闭、aria 属性、滚动锁定、焦点恢复），样式完全交给使用方——与 WES 基于 `tokens.css` 的自研样式体系天然相容，不会像 shadcn/ui 那样绑定 Tailwind
2. **行为细节经过大规模生产验证**：每个组件的键盘导航、屏幕阅读器语义、嵌套弹出层焦点管理都经过数千项目的实战打磨，这是自研组件最容易遗漏、最花时间的部分
3. **API 设计即文档**：每个原语的 props、事件、受控/非受控模式设计干净一致，即使不安装代码，其行为规格也可直接作为自研组件的对照基准

### 对 WES 的具体启发点

1. **`ui/V2_PROTOTYPE/src/components/ui/` 组件底座补强**：当前自研组件仅 3 个——`Dialog.jsx`、`Drawer.jsx`、`ToastContainer.jsx`。AGENTS.md 已约定「全局弹窗默认支持顶部空白区拖拽」「表格行级编辑默认用 Dialog」「复杂说明用 `?` Tooltip 入口」，这些交互的**无障碍语义**（键盘 Esc 关闭、焦点陷阱、Tab 循环、打开/关闭时焦点恢复、aria-modal）正是 Radix 每个原语的内建行为，可逐条对照审计自研组件的缺口并补齐
2. **Tooltip 原语的缺失填补**：AGENTS.md 明确要求「控件旁用 `?` Tooltip 入口」，但当前组件目录中并无 Tooltip 组件。Radix Tooltip 的延迟显示/取消机制（hover 延迟、移入其他触发点不闪、长内容可 hover 内部）是可移植的行为规格
3. **Toast 通知的交互补齐**：`ToastContainer.jsx` 现有实现可对照 Radix Toast 补上「悬停暂停自动关闭、Esc/点击关闭、键盘可达性」等生产级细节

### 可能的应用场景与实施建议

| 维度 | 说明 |
|------|------|
| 落地路径 | 两条路：① 零依赖路线——以 Radix 行为规格为基准，逐条补齐自研 `Dialog/Drawer/Toast` 的无障碍缺口（不新增依赖）；② 按需引入路线——经架构决策后仅引入 Tooltip/Popover 等 WES 尚无自研实现的个别原语。按 AGENTS.md「未经独立架构决策不得引入新的 UI 技术栈或组件系统」，建议先走①，确需原语时走② |
| 引入成本 | ① 约 0 成本（对照审计 + 补齐，1-2 人天）；② 单组件 npm 包按需引入，每个约几十 KB |
| 预期收益 | 键盘用户与屏幕阅读器用户可用性显著提升；弹窗/Tooltip 交互行为与业界最佳实践对齐；为 Phase B 组件库沉淀行为基准 |
| 风险提示 | ② 需过架构决策门禁；Radix 无样式，视觉仍依赖 WES 自己的 CSS，两路线均不改变现有视觉体系 |

## 2. electric-sql/pglite — WASM 内嵌 PostgreSQL 测试基建

| **综合总分** | | | **8.25** |

### 基本信息

| 字段 | 值 |
|------|-----|
| 仓库全名 | `electric-sql/pglite` |
| 链接 | https://github.com/electric-sql/pglite |
| Star 数 | 15,805 |
| 最近推送 | 2026-08-13（当日活跃） |
| 许可证 | Apache-2.0 |
| 技术栈 | TypeScript（PostgreSQL 编译为 WASM） |
| 描述 | 可在 Node.js / 浏览器进程中内嵌运行的完整 PostgreSQL（WASM 版），带实时响应式绑定 |

### 核心亮点

1. **真 PostgreSQL，非模拟**：不是 SQL 子集仿制（区别于 pg-mem 等），而是把完整 PostgreSQL 编译成 WASM，drizzle-kit 迁移、标准 SQL、事务语义在进程内直接可跑
2. **零基础设施**：不需要 Docker daemon、不需要外部数据库实例——`new PGlite()` 即得一个可用数据库，测试环境一分钟就绪
3. **drizzle-orm 原生适配**：drizzle-orm 官方提供 `drizzle-orm/pglite` driver，与 WES Harness 域已采用的 drizzle 技术栈同源同门

### 对 WES 的具体启发点

1. **消除 Harness 域测试的「静默跳过」**：`apps/api/src/modules/harness/harness-session-projector.test.ts` 中多个关键用例（T9a/T9b/T9c 消息投影与重放、Batch E 消息落库端到端）均为 `{ skip: !testDatabaseUrl }`——**没有 `TEST_DATABASE_URL` 时这些 DB 集成测试整段跳过**，测试套件假绿。PGlite 让这些用例在任意环境（CI、新开发者机器）始终真实运行，无需先备好 PostgreSQL 或 Docker
2. **凭据域测试同样受益**：凭据域是第二个 DB-backed 域（加密落库 + 变更审计），其 repository 测试同样需要一个进程内 PG；PGlite 一次引入、两域共用
3. **devDeps 现状的互补定位**：WES 已有 `@testcontainers/postgresql`（需 Docker 常驻），PGlite 与之互补——Docker 可用时用 testcontainers 做最接近生产的验证，不可用时用 PGlite 保证测试不被跳过

### 可能的应用场景与实施建议

| 维度 | 说明 |
|------|------|
| 落地路径 | 测试 fixture 中增加 PGlite 分支：`TEST_DATABASE_URL` 缺失时启动 PGlite 实例并执行 drizzle 迁移，将 `skip` 改为「三选一：TEST_DATABASE_URL → testcontainers → PGlite」；生产路径零改动（真实 PostgreSQL 不变） |
| 引入成本 | 低。`npm i -D @electric-sql/pglite`，fixture 封装约 0.5 人天；无 Docker 依赖、无镜像拉取 |
| 预期收益 | DB 集成测试从「多数环境跳过」变为「全环境真跑」，消息投影/重放这类曾反复出缺陷的链路（Batch E 二次返工教训）获得持续回归保护 |
| 风险提示 | PGlite 不覆盖部分 PostgreSQL 扩展与跨进程特性（如 LISTEN/NOTIFY 跨进程、部分扩展），若 Harness 用到 `FOR UPDATE SKIP LOCKED` 等特性需先行验证兼容性；定位是「测试替身」，不能替代 staging 上的真实 PG 验证 |

## 本次总结

- **入选 3 个项目**，按评分排序：radix-ui/primitives（8.50，无障碍组件原语）> electric-sql/pglite（8.25，内嵌 PostgreSQL 测试基建）> apache/echarts（7.90，数据可视化）
- **核心主题**：今日三个项目对应 WES 三条已验证的真实缺口——① 前端自研组件（Dialog/Drawer/Toast）缺少无障碍行为基准（Radix 提供）；② Harness/凭据域 DB 测试在无 `TEST_DATABASE_URL` 时整段静默跳过（PGlite 让测试全环境真跑）；③ 18 个前端页面零图表能力（ECharts 补上屏上可视化）
- **实施优先级建议**：PGlite（成本最低 0.5 人天、直接修复测试假绿）→ Radix 行为对照审计（零依赖、1-2 人天）→ ECharts 按需引入（视评估可视化需求排期）
