# Prompt 最佳实践

> 来源：https://platform.kimi.com/docs/guide/prompt-best-practice

## 编写清晰的说明

### 在请求中包含更多细节
为了获得高度相关的输出，请保证在输入请求中提供所有重要细节和背景。

| 一般的请求 | 更好的请求 |
|-----------|-----------|
| 如何在Excel中增加数字？ | 我如何在Excel表对一行数字求和？我想自动为整张表的每一行进行求和，并将所有总计放在名为"总数"的最右列中。 |

### 要求模型扮演一个角色
在 `messages` 中增加指定模型在回复中使用的角色。

### 使用分隔符来明确指出输入的不同部分
使用三重引号/XML标签/章节标题等定界符帮助区分需要不同处理的文本部分。

```json
{
  "messages": [
    {"role": "system", "content": "你将收到两篇用XML标签分割的文章。首先概括每篇文章的论点，然后指出哪篇提出了更好的论点。"},
    {"role": "user", "content": "<article>文章1</article><article>文章2</article>"}
  ]
}
```

### 明确完成任务所需的步骤

```json
{
  "messages": [
    {"role": "system", "content": "使用以下步骤回应。\n步骤一：将文本概括成一句话。\n步骤二：翻译成英语。"},
    {"role": "user", "content": "\"\"\"文本内容\"\"\""}
  ]
}
```

### 向模型提供输出示例（Few-shot 提示）

### 指定期望模型输出的长度
可要求特定目标长度，但精度有限。模型更擅长生成特定数量的段落或项目符号。

## 提供参考文本

### 指导模型使用参考文本来回答问题

```json
{
  "messages": [
    {"role": "system", "content": "使用提供的文章回答问题。如果答案找不到，请写'我找不到答案。'"},
    {"role": "user", "content": "<文章用三引号分隔>"}
  ]
}
```

### 对轮次较长的对话应用程序，总结或过滤之前的对话
由于模型有固定的上下文长度限制，对话不能无限期继续。可以：
- 总结对话中的前几个回合
- 异步总结整个对话
