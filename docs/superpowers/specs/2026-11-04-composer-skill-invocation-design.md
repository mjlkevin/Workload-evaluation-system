## 交互与边界

1. 光标前的独立 `/关键词` 打开授权目录，按名称、简介和类型过滤；上下键选择、Enter 选中、Escape 关闭。选中仅改变草稿，不启动任务；移除对应命令片段，保留前后正文，并将焦点留在编辑区。URL 中的斜杠不触发。
2. 一次一项 Skill / Workflow，以标签展示类型与名称，支持移除。保留附件和提示词；无标签时沿用普通聊天发送。
3. 点击发送或 Enter 才执行。仅对契约声明的顶层 `text` / `description` / `instructions` 字符串字段，或根字符串输入，用提示词填充；不猜测项目名、模板或其他业务字段。不符合契约时用既有 BusinessInputForm 和 Dialog 补齐，取消返回原草稿。
4. 业务附件沿用 execution-sources 接口及其 2 MiB / xlsx、txt、md 限制；上传失败不启动，不退回普通聊天。重复提交使用稳定 submissionKey，成功后才清空原草稿，失败保留全部输入。
5. 切换会话、用户或卸载使旧异步结果失效；旧请求不得启动新会话任务或清掉新草稿。沿用当前服务端授权、版本冻结、写确认及 Harness，没有后端契约变更。

## 方案取舍

采用 textarea + 独立标签 + 原生 listbox，不引入编辑器依赖。contenteditable 内联 token 会扩大光标、输入法与粘贴处理范围；保留原选择弹窗无法满足统一发送，因此不采用。

唯一表面：`/` 的 AiHomeWorkbench 输入区。三个根问题：独立按钮/弹窗打断消息输入；选择与提示词附件脱节；选中即独立启动的时机不符合消息发送习惯。

确定归属：Composer 管命令清单和标签；专用调用 hook 管输入校验、会话/上传/提交生命周期；参数 Dialog 复用 BusinessInputForm。列表仅显示当前用户可调用目录，不新增 UI 技术栈。新代码采用 AGENTS 已批准的 Tailwind tokens 桥接（优先于 UI Skill 的历史限制）。
