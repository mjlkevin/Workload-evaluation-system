# RP-031 智谱知识库可信运行与效果评测设计

## 1. 目标

在不重建智谱知识库接入、不引入第二套前后端或数据库迁移的前提下，把当前已经可用的“后台配置 → 连通性测试 → AI 工作台检索 → 基于文档回答 → 降级与基础 Trace”链路补成可安全激活、可调参、可追踪、可重复评测的生产闭环。

完成后，管理员可以证明一份知识库配置已经通过真实访问验证；产品与质量负责人可以用固定样本比较当前配置和一个候选配置；候选配置只有满足质量、延迟与成本门槛时才建议进入人工激活。

## 2. 当前基线

当前主线已经具备：

- 管理员配置 API Key、知识库 ID、模型和智谱 API 地址；支持草稿、激活、密钥掩码和环境变量回退。
- 真实调用智谱检索接口测试连通性；HTTP 200 但零命中时返回成功并提示 `retrieval_empty`。
- AI 工作台识别 `knowledge_query`，先检索文档，再基于文档生成回答，并显示来源数量、最高相关度、置信度和降级原因。
- 检索失败或生成失败时提供明确降级，不自动改写正式评估或业务记录。
- 统一 Trace 已记录知识库 span 的命中数量、最高分、Token、模型和降级原因。
- `runRagBaseline` 已能对样本统计关键词命中、文档召回、延迟、置信度和 fallback，但还没有正式执行入口、版本指纹、报告持久化与候选对比。

本设计复用上述能力，不另建知识库客户端、问答页面或评测技术栈。

## 3. 范围与明确排除

### 3.1 本次范围

1. 安全与激活门禁：真实密钥清除、统一出站地址策略、测试结果与配置 hash 绑定、24 小时有效期、干净 checkout 安全扫描、路由权限回归。
2. 检索配置与追踪：TopK、TopN、召回方式、重排、阈值可配置并进入正式请求；Prompt Registry；HTTP request ID、供应商 request ID、Prompt 与配置版本进入统一 Trace。
3. 评测 MVP：至少 20 条脱敏样本、明确的版本指纹、内部 CLI、JSON 报告持久化。
4. 单候选对比：当前激活配置与一个候选配置执行同一数据集，输出质量、fallback、P95 延迟与 Token 差异及建议结论。

### 3.2 不在本次范围

- PostgreSQL 或 JSON + PostgreSQL 双写；知识库配置继续使用现有 JSON Repository。
- 多知识库、多 Provider、Query Rewrite、RRF、分布式缓存、断路器、大型监控看板。
- 自动激活候选配置；评测只能给出建议，正式激活仍由管理员人工执行。
- 新 UI 技术栈、组件库或第二个知识库管理页面。

## 4. 架构设计

### 4.1 单一配置权威

`system.repository.ts` 继续负责知识库 JSON store。配置分为 draft 和 active，并增加：

- `retrievalParams`：`topK`、`topN`、`recallMethod`、`rerankEnabled`、`rerankModel`、`fractionalThreshold`。
- `promptProfile`：当前回答 Prompt 的 ID 和版本。
- `probe`：最近一次真实探针结果、配置 hash、时间、供应商 request ID 和错误摘要。

凭证三态保持明确：字段省略表示保留，非空表示替换，`null` 表示清除。API 永远不回传明文密钥。

### 4.2 统一出站策略

新增一个独立 URL policy，探针、正式检索和正式生成必须调用同一个校验函数。默认仅允许 HTTPS `open.bigmodel.cn`，禁止用户信息、非默认端口和重定向；任何非法地址在发起网络请求前失败。

### 4.3 测试后激活

管理员测试时对去除密钥明文后的草稿配置与密钥指纹计算 hash，并保存探针结果。激活必须同时满足：

- 最近探针成功；
- 探针对应 hash 与当前草稿完全一致；
- 探针时间不超过 24 小时。

修改模型、地址、知识库 ID、检索参数、Prompt 或密钥后，原探针自动失效。

### 4.4 请求与 Prompt 追踪

沿用 HTTP `X-Request-Id` 作为本次请求编号，并传给智谱检索和生成请求。解析供应商响应中的请求编号，和 Prompt `id/version/hash`、知识库配置版本、检索参数一起进入 `knowledge_retrieval` span。Trace 查询继续复用现有 owner/admin 权限隔离。

### 4.5 评测与比较

评测样本使用受控 JSON 文件，至少包含 20 条脱敏问题、期望关键词、期望文档以及无答案标记。Runner 每条样本只执行一次知识库问答并复用返回 chunks，不产生重复检索。

报告包含：

- dataset、知识库配置、知识快照、Prompt、scorer 的版本指纹；
- 关键词命中率、文档召回率、fallback 率、高置信度率、平均/P95 延迟、平均 Token；
- 每条样本的回答、引用、得分和降级原因；
- 当前配置与候选配置的差异以及 `recommended` / `not_recommended` 结论。

建议门槛：关键词命中率或文档召回率至少提升 5 个百分点；另一项下降不超过 2 个百分点；fallback 不增加；P95 延迟增加不超过 20%；平均 Token 增加不超过 15%。门槛只产生建议，不自动激活。

报告写入被 Git 忽略的运行目录，日志与报告不得包含 API Key。

## 5. 管理页面

唯一 UI 业务表面为 `/system/knowledge-base`：

- 保留现有保存、生效、测试及内联反馈模式。
- 增加显式“清除已保存密钥”动作，避免只清空输入框造成误解。
- 增加检索参数区域，复用现有 input/select/token，不引入新依赖。
- 激活失败时显示“需要重新测试”或“测试已过期”等可操作原因。

本次不在页面增加评测大屏；评测先通过内部 CLI 生成报告，避免扩大 UI 范围。

## 6. 错误与降级

- 非法地址、缺失凭证、401/403、429、5xx、业务错误码、网络错误和超时分别保留可判断的错误原因。
- 零命中表示“接口可达但没有文档”，探针可成功但附带警告；正式问答继续使用现有通用模型降级和反幻觉提示。
- 生成失败时保留检索到的文档摘要，不伪造正式回答。
- 评测中单样本失败记录为结果，不中断整批；无法加载数据集或配置时整批失败。

## 7. 验收与门禁

### 自动化

- 安全扫描在干净 checkout 和存在本地 ignored 配置两种环境均可运行。
- 后端覆盖凭证三态、URL policy、probe/hash/过期、权限、检索参数、Prompt、request/provider ID Trace。
- Web 覆盖清除已保存密钥、检索参数保存、激活门禁错误和现有内联反馈。
- 评测覆盖 20 条数据集解析、版本指纹、P95、报告脱敏、单候选比较与门槛结论。
- 全量 modules、AI、integration、Web 与 API/Web build 通过。

### 人工

- 管理员使用真实智谱凭证验证成功、零命中、错误凭证、清除凭证和修改配置后重测。
- `/system/knowledge-base` 在 1440px 与 760px 下完成键盘、反馈和操作可达性检查。
- 真实 20 条评测需要 owner 可用凭证；未执行前只能标记“自动化完成 / 真实评测待回填”。
