# Skill 作为对话能力上下文

用户已于 2026-11-04 明确确认：选择 Skill 只是将能力和上下文带给 LLM，问用途就介绍，有任务才执行，信息不足先追问。关联 ISS-2026-11-04-002 / DEF-2026-11-04-001 / RP-050。

## 范围与选择
仅修改 AI 工作台的带标签消息通道（Skill 与 Workflow 一致）。保留普通聊天、管理发布生命周期与现有任务执行器。采用服务端 LLM 对话判断，而非客户端关键词路由；相比直接改发布定义，能同时纠正所有标签的触发语义；相比重写通用 Agent，边界更小，复用执行和确认体系。

## 行为
选择标签不发请求。发送后，服务端读取当前有权访问的发布定义、会话历史、原文附件和引用材料，向对话模型提供能力说明与输入契约。模型返回自然语言答复(reply)、追问(clarify)或任务执行意图(execute + 输入)。能力询问与不适用输入不能强行填需求，缺失参数不能猜测。对话输出不受所选 Skill 的业务结果 Schema 约束；只有真实执行继续遵守该 Schema。

reply/clarify 在中央消息流原子持久化用户消息和助手答复，不创建 Harness 任务；标签保留，用户可以继续补充。刷新可恢复最后的对话标签。execute 经输入契约校验、当前版本与权限复核后调用现有 submitInvocation；工具写入仍等待独立确认。附件原文引用保留到后续澄清，执行时携带这些引用。已发布 Skill 定义不修改。

## 安全与重试
HTTP 只接受会话ID、提交键、用户文本、选择的种类/ID/版本及受控来源引用。禁止客户端传定义、历史、模型或工具。上下文均从服务端归属校验后读取；模型判断不能授予工具权限。决策调用不提供业务工具，只有执行通道具备工具能力。响应、超时、用量与大小校验失败时保留草稿且不执行。回复按提交键与内容指纹原子去重；执行通过确定性提交键复用既有队列幂等机制。模型等待不持数据库锁，返回后重新校验上下文与权限，变更则拒绝。

## 验证
先写失败测试：用途问答不启动、信息不足追问、多轮补充才启动、真实任务原文与附件传递、刷新恢复、失败/双击/切会话隔离。服务端覆盖伪造上下文/越权/版本变更/坏模型结果/输入契约/重放冲突。浏览器真实模型验证用途、追问、补充执行及刷新；结构测试与真实语义结果分开记录。Web/API构建、Web回归、模块测试和UI范围检查如实留存。
