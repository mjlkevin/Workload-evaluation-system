# WES 用户管理侧栏编辑与操作分层设计

## 1. 背景与决策

RP-043 的 SystemManagement 共享 Dialog 试点已完成自动化验证，用户在真实使用后确认“效果很稳定”，并授权继续推进其他 UI 优化。下一批限定为 `/users` 用户管理页面族，不扩展为全站重构。

本轮通过真实管理员会话审计了用户列表、用户选择、系统角色弹窗、密码重置弹窗和 760px 状态，并比较了三档方案：

- A：只迁移四个页面内 Dialog；
- B：迁移 Dialog，同时重排工具栏；
- C：在 B 的操作分层基础上，为单用户维护增加右侧侧栏工作区。

用户于 2026-07-25 选择并确认方案 C。

治理追踪：

- 原始问题：`ISS-2026-07-25-003`
- 派生需求：`RP-043`
- 关联缺陷：`ISS-2026-07-04-002 / DEF-2026-07-04-002`（邀请成员按钮无响应）
- 关联需求：`ISS-2026-07-04-003 / RP-041`（管理员直接新建用户）
- 本轮去重结果：属于 RP-043 既定 D 批“试点通过后扩展其他 Dialog”，不新增重复 Issue 或 RP

## 2. 已证实根问题

本批只处理以下三个根问题，其余观察保留为候选。

### 2.1 操作模型混杂且存在虚假可供性

- “已选 N”、五个批量动作、邀请成员、两个装饰性筛选和搜索挤在同一工具条。
- 行内“编辑”没有独立编辑行为，点击后只通过事件冒泡改变行选择。
- 当前实际代码中的“邀请成员”没有 `onClick`，与既有 DEF-2026-07-04-002 的“已修复待复核”记录不一致。
- 系统角色和状态操作只修改页面本地状态，未调用已经存在的持久化接口。

### 2.2 弹窗缺少统一语义、键盘能力与目标上下文

- `UserManagement.jsx` 自带 `DialogBackdrop`、`DialogCard`、`DialogActions`，绕过已经验证的共享 Dialog owner。
- 浏览器证据显示弹窗没有可识别的 dialog 语义，Escape 不关闭。
- 密码重置弹窗用长用户名挤压标题区；批量角色弹窗只显示人数，不清楚展示目标范围。

### 2.3 单用户维护路径割裂且缺少未保存保护

- 系统角色、业务角色、状态和密码分散在批量工具条与多个弹窗中。
- 单用户操作仍需先“选择”，再回到顶部寻找动作。
- 页面没有草稿、脏状态、关闭保护和统一保存反馈，容易出现“改了什么、是否已保存”不清楚。

## 3. 目标

1. 让单用户维护形成“列表定位 → 行内编辑 → 侧栏复核 → 保存”的连续路径。
2. 让批量操作仅在真实选择后出现，并与页面主动作、筛选和搜索分层。
3. 将用户管理弹窗迁移到共享 Dialog，补足语义、焦点、Escape、目标摘要和高风险确认。
4. 复用现有后端接口完成真实持久化，不再使用只改前端内存的假保存。
5. 保持 Vite + React、现有 CSS Token、API 访问层与权限模型，不引入新 UI 依赖。

## 4. 非目标

- 不新增页面或路由。
- 不改动 JWT、角色权限规则、用户 JSON 数据结构或后端接口语义。
- 不实现新的批量事务接口；现有多个 PATCH 仍是非原子操作。
- 不把 RP-041“管理员直接新建用户”混入本批；如果该功能未集成，页面不得伪造一个可用入口。
- 不重做角色能力矩阵，不改变其数据来源。
- 不迁移 UserManagement 之外的 Dialog。
- 不新增 Tailwind、Radix、Motion 或第二套组件系统。

## 5. 页面信息架构

### 5.1 页面标题区

- 保留“用户管理 / 用户、角色与状态管理”。
- 页面级主动作放在标题区右侧：
  - 已有并可验证的邀请流程存在时，显示 `+ 邀请成员`；
  - 若当前分支仍缺少对应行为，则本批先恢复 DEF-2026-07-04-002 的既有邀请流程并迁移其弹窗；
  - `+ 新建用户` 仅在 RP-041 已完成独立集成并通过测试时显示，本批不重新实现。

页面不得保留点击无响应的主按钮。

### 5.2 筛选与搜索行

- 将系统角色、状态和搜索从批量动作中拆出。
- 系统角色筛选支持：全部、超级管理员、管理员、普通用户。
- 状态筛选支持：全部、正常、已禁用。
- 默认“全部”不显示伪关闭符号。
- 筛选和搜索均在当前已加载用户数据上执行，不新增后端查询接口。
- 筛选变化后，清理已经不在可见结果中的选择，避免对不可见对象执行批量动作。

### 5.3 用户表格

- 复用现有列、角色 chip、状态 chip 和系统账号锁定表现。
- 行点击继续用于单选；复选框、Shift、Ctrl/Command 多选规则保持不变。
- 行内“编辑”拥有独立 `onClick`，并阻止冒泡，不再改变批量选择。
- 继续沿用当前“超级管理员行按系统账号保护、不可在列表编辑”的页面规则；本批不借 UI 优化改变权限边界。
- 其操作列保持“系统账号”说明。
- 打开单用户侧栏不会隐式改变当前批量选择。

### 5.4 上下文批量操作条

- `selected.size === 0` 时不渲染批量动作条。
- 选择至少一名用户后，在筛选行与表格之间出现上下文条，显示：
  - 已选 N 人；
  - 清除选择；
  - 批量启用 / 禁用；
  - 改系统角色；
  - 改业务角色。
- “重置密码”从批量动作条移除，只放在单用户侧栏的安全操作区。
- 批量角色和状态修改必须调用现有后端接口；成功后再更新页面数据。

## 6. 单用户侧栏工作区

### 6.1 组件 owner

新增共享 `ui/V2_PROTOTYPE/src/components/ui/Drawer.jsx`，作为右侧 modal sheet owner。它不扩展或改变现有 `Dialog.jsx` 的居中、可拖拽行为。

Drawer 负责：

- `role="dialog"`、`aria-modal="true"`、标题和可选描述关联；
- 初始焦点、Tab 环、Escape 请求关闭、关闭后焦点恢复；
- 可见关闭按钮和遮罩；
- 头部、可滚动 body、固定 footer；
- 由调用方决定遮罩点击和关闭请求是否可直接执行；
- 侧栏本身固定在右侧，不支持拖拽。

Drawer 属于锚定式侧栏工作区，不是浮动弹窗，因此不适用“弹窗顶部可拖拽”约定；它触发的密码、风险和放弃修改 Dialog 继续复用共享 Dialog 的顶部拖拽能力。

桌面宽度为 `min(440px, 100vw)`；760px 及以下改为全宽工作区，高度不超过 `100dvh`，footer 始终可达。

### 6.2 侧栏内容

头部：

- 标题：编辑用户；
- 描述：用户名，长文本单行省略并通过 `title` 或 Tooltip 提供完整值；
- 关闭按钮。

账户信息：

- 用户名、邮箱、最后登录只读；
- 系统角色、业务角色、账户状态可编辑；
- 初始草稿来自所打开行的服务器数据快照。

安全操作：

- 重置密码；
- 启用或禁用账户的显式动作入口。

footer：

- 取消；
- 保存变更；
- 无字段变化时保存按钮禁用；
- 保存中显示稳定进行态并防止重复提交。

### 6.3 保存状态机

1. 比较初始快照与草稿，仅提交变化字段。
2. 系统角色使用 `PATCH /auth/users/{userId}/role`。
3. 业务角色使用 `PATCH /auth/users/{userId}/business-role`。
4. 状态使用 `PATCH /auth/users/{userId}/status`。
5. 不进行成功前的乐观更新。
6. 全部成功后：
   - 更新列表行；
   - 清除脏状态；
   - 关闭侧栏；
   - 在页面区域显示保存成功反馈。
7. 任一请求失败后：
   - 停止后续请求；
   - 重新读取用户列表，以服务器事实为准；
   - 保持侧栏打开；
   - 明确提示可能已经保存的字段和失败字段，避免把多 PATCH 伪装成原子事务。

请求顺序为业务角色 → 系统角色 → 状态；风险最高的状态修改最后执行。

### 6.4 高风险确认

- 如果未来或测试数据中出现可编辑的超级管理员，从超级管理员降权时，在真正提交角色 PATCH 前打开共享 Dialog，要求输入“我确定”。
- 当前生产页面仍保护全部超级管理员行，本批不为了展示降权流程解除锁定；降权 Dialog 作为防御性兼容路径迁移并保留测试。
- 从正常改为禁用时，在真正提交状态 PATCH 前打开共享 Dialog，显示用户名、当前状态和目标状态。
- 同一次保存同时包含降权与禁用时，只显示一次复合风险确认，列出两项变化；仍需输入“我确定”。
- 重置密码始终使用独立共享 Dialog，不作为侧栏普通保存字段。
- 高风险 Dialog 默认不允许点击遮罩关闭，Escape 只返回侧栏且保留草稿。

### 6.5 未保存关闭保护

- 侧栏无修改时，关闭按钮、Escape、取消和遮罩可直接关闭。
- 存在未保存修改时，任何关闭请求都打开共享“放弃未保存修改”Dialog。
- 确认放弃后关闭侧栏并恢复触发“编辑”的按钮焦点。
- 继续编辑则关闭确认 Dialog，侧栏草稿保持不变。

## 7. 批量操作与邀请流程

### 7.1 批量操作

- 批量系统角色、业务角色迁入共享 Dialog，并显示目标人数与最多前三个用户名摘要。
- 批量启用/禁用使用共享确认 Dialog；禁用使用危险按钮样式。
- 对每个目标按现有单用户接口逐项提交，不声明原子性。
- 失败时报告成功数、失败数和失败用户名；重新加载服务器用户列表。

### 7.2 邀请成员

- 将 DEF-2026-07-04-002 视为既有行为恢复，不设计新的邀请业务模型。
- 使用现有邀请码生成接口。
- 结果通过共享 Dialog 展示，并提供明确复制操作与有效期信息。
- 若当前接口、权限或响应结构与既有记录不一致，停止并回到 DEF-2026-07-04-002 做证据回填，不在 UI 层伪造成功。

## 8. 错误与反馈

- 页面级加载失败继续显示用户列表错误，不使用 fallback 数据伪装真实成功。
- 字段校验和请求错误显示在侧栏或 Dialog 内，不使用浏览器 `alert`。
- 保存、重置密码、邀请和批量操作均需要进行态与终态反馈。
- 权限错误保留后端消息，但不暴露敏感内部字段。
- 所有成功反馈必须基于服务端成功响应。

## 9. API 与文档对齐

本批不新增后端接口，但会正式依赖以下现有路由：

- `GET /api/v1/auth/users`
- `PATCH /api/v1/auth/users/{userId}/role`
- `PATCH /api/v1/auth/users/{userId}/business-role`
- `PATCH /api/v1/auth/users/{userId}/status`
- `PATCH /api/v1/auth/users/{userId}/password`
- 既有邀请码生成接口

当前 `docs/openapi.yaml` 已记录用户列表、系统角色、状态和邀请码接口，但未找到业务角色与密码接口。实施交付前必须补齐这两个既有接口的 OpenAPI 契约。只做文档对齐，不改变接口实现。

## 10. 测试策略

### 10.1 TDD 顺序

先写失败测试并观察 RED，再实现最小 GREEN：

1. Drawer primitive：语义、焦点、Escape、遮罩、焦点恢复、窄屏 class。
2. 行内编辑：打开目标用户、阻止行选择、系统账号不可编辑。
3. 草稿与关闭保护：脏状态、放弃/继续编辑。
4. 单用户保存：只提交变化字段、请求顺序、成功关闭、失败保留并刷新。
5. 高风险确认：降权、禁用、复合确认。
6. 密码重置：从侧栏打开共享 Dialog，既有 API 行为保持。
7. 上下文批量条：零选择隐藏，多选出现，清除选择。
8. 筛选：系统角色、状态、搜索组合过滤。
9. 邀请成员：恢复既有 DEF 行为，按钮不再静默。

### 10.2 自动化

- `npm run test --prefix ui/V2_PROTOTYPE -- src/__tests__/Drawer.test.jsx`
- `npm run test --prefix ui/V2_PROTOTYPE -- src/__tests__/UserManagement.test.jsx`
- `npm run test:web`
- `npm run build:web`
- 如果 OpenAPI 文档变更，运行项目既有契约/文档校验命令。

### 10.3 浏览器验收

使用有效管理员会话检查：

- 桌面：默认列表、筛选、选择条、侧栏、保存成功/失败、高风险 Dialog。
- 760px：列表可达、侧栏全宽、body 可滚动、footer 可达。
- 键盘：编辑按钮 → Drawer 初始焦点 → Tab 环 → Escape → 放弃确认 → 关闭后焦点恢复。
- 不提交真实破坏性数据；需要验证写入时使用可恢复测试用户并记录恢复步骤。
- 控制台无新增 warning/error。

## 11. 验收口径

- 单用户“编辑”是独立、可预测、可持久化的工作流。
- 批量操作、页面主动作、筛选搜索在视觉和行为上分层。
- 页面不再包含自建 Dialog helper，所有确认与密码弹窗使用共享 Dialog。
- Drawer 满足语义、焦点、Escape、关闭保护与 760px 可达性。
- 角色、业务角色和状态修改使用真实 API；不再只改本地内存。
- 邀请成员按钮不再点击无响应。
- 无新增前端依赖，无第二组件栈。
- 聚焦测试、V2 全量测试和 Web 构建通过。
- 浏览器桌面、窄屏和键盘证据可复查。
- RP-043、关联 DEF/RP、设计、测试、风险、来源与变更记录互相可追溯。

## 12. 分批与停止条件

1. 批次 D1：Drawer primitive 与 RED/GREEN 测试。
2. 批次 D2：用户管理信息架构、筛选、上下文批量条和行内编辑。
3. 批次 D3：单用户保存、高风险确认、密码与批量 Dialog 迁移。
4. 批次 D4：邀请行为恢复、OpenAPI 对齐、全量验证和浏览器验收。

出现以下情况时停止扩展并回到设计或关联事项：

- 需要新增后端批量事务接口；
- RP-041/DEF-2026-07-04-002 与当前代码无法安全对齐；
- 真实权限规则与页面可编辑范围冲突；
- 需要引入新 UI 依赖；
- 无法取得有效管理员会话完成真实页面验证。
