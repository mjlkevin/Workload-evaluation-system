# RP-036 登录态与系统配置可信反馈设计

## 背景

系统管理的知识库配置页在本地仍保留失效登录态下的页面内容。此时
`useSystemManagement` 的 `enabled` 为 `false`：

- 保存草稿跳过 PATCH，却仍弹出成功提示；
- 测试连通性直接返回 `null`，页面结束 loading 后不展示任何结果。

这会让管理员误判配置已经持久化或连通性测试已经执行。

## 目标

1. 无有效 JWT 时，受保护页面直接进入登录页，不渲染业务 Shell。
2. 普通用户不能进入 `/system`、`/users`、`/api-keys` 等管理员路由。
3. 知识库草稿成功提示只能出现在 PATCH 成功之后。
4. 连通性测试点击后立即 loading，并在成功、鉴权失效、超时或其他失败时展示明确结果。
5. 不读取、记录或回显完整 API Key，不改变后端接口与权限契约。

## 方案比较

### 方案 A：路由、动作、请求三层闭环（采用）

路由入口校验 JWT 和当前用户角色；Hook 对禁用状态返回显式错误；连通性请求设置有限超时；页面统一渲染结果。改动覆盖初始失效登录、页面停留期间失效和上游无响应三类场景，范围仍限定在现有鉴权与知识库配置链路。

### 方案 B：只修知识库按钮

仅移除无条件 alert 并把 `null` 改为错误对象。改动最小，但失效登录态仍能看到并操作管理员页面，其他系统配置动作仍可能产生相同问题，不能满足 RP-036 的入口门禁要求。

### 方案 C：只依赖 API 401 跳转

所有动作都发请求，由 API 客户端收到 401 后跳转。无法处理页面初始加载时无 token 的静默禁用，也无法阻止普通用户先看到管理员页面，因此不采用。

## 设计

### 鉴权入口

- `isAuthenticated` 在 token 存在时检查可解析 JWT 的 `exp`；已过期则清除 token 并返回未登录。测试或兼容场景中的非 JWT token 保持“存在即有效”，最终身份仍由 `/auth/me` 确认。
- `App` 将登录和重置密码保留为公开路由，其余路由进入统一受保护布局。
- 受保护布局调用 `/auth/me`。加载完成前不渲染 Shell；失败或用户为空时跳转登录；管理员路由遇到普通用户时跳回 AI 工作台。
- `Shell` 接收入口已确认的用户，管理员导航只对 admin 显示；独立渲染 Shell 时仍可自行加载当前用户，兼容既有测试与组件用法。

### 配置动作反馈

- `saveKbDraft` 在未启用时返回失败结果，不发送请求、不弹成功提示。
- PATCH 成功后才弹出“知识库配置草稿已保存”；失败由 `withAction` 形成 `{ success: false, error }`。
- `testKbConnectivity` 在未启用时返回 `{ ok: false, code: 'UNAUTHORIZED' }`，不再返回 `null`。
- 页面保存按钮和测试按钮均在请求期间禁用；保存失败与测试结果都使用页内状态卡展示，避免只依赖瞬时 alert。

### 超时

API 客户端接受可选 `timeoutMs`。只有连通性测试传入 30 秒，超时后中断 fetch 并返回“请求超时，请稍后重试”。其他请求行为保持不变。

## 验证

- AuthGuard：过期 JWT 跳登录、普通用户离开管理员路由、管理员可进入系统管理。
- Hook：禁用状态不产生假成功；PATCH 失败不弹成功；测试禁用、超时、成功均返回结构化结果。
- 页面：点击后显示 loading，最终显示成功或失败状态。
- 执行前端定向测试、前端全量测试、`npm run build:web`；再运行 `npm run build:api` 证明接口契约未被破坏。
