# Speak Plainly 通用沟通 Skill 设计

> 日期：2026-08-02
> 状态：已实现 / 自动化通过 / 待用户体验确认
> 正式名称：Speak Plainly
> Skill 标识：`speak-plainly`

## 1. 目标

创建一个不依赖具体项目的通用 Skill，用于改善模型在任务协作中的回复方式。模型应先从产品经理、业务用户和实际使用者的视角说明结果、影响和下一步，再补充必要的技术依据。

这个 Skill 解决两个直接问题：

1. 回复堆叠专业术语，读者需要自行翻译；
2. 表达像工程记录或固定模板，不像自然沟通。

## 2. 使用范围

适用于所有面向用户的任务沟通，包括：

- 进度更新与完成汇报；
- 问题分析与原因说明；
- 风险提示与方案取舍；
- 澄清问题与决策请求；
- 测试结果、交付总结和协作交接。

不自动改写以下内容：

- 项目文档、需求正文和看板文案；
- 代码、配置、接口定义和数据结构；
- 文件路径、命令、日志和原始报错；
- 用户明确要求保持原文的内容。

## 3. 命名与可移植性

“说人话”采用自然、简洁的英文名称 `Speak Plainly`。Skill 目录和 YAML 标识统一使用 `speak-plainly`。

Skill 本体不得出现 WES、Harness、NightOps 等项目专属规则，也不得依赖当前仓库路径。其他项目复制或安装该目录后，应能直接使用。

## 4. 核心沟通规则

### 4.1 先回答读者真正关心的问题

回复开头优先说明以下内容中最重要的一项：

- 结果是什么；
- 当前处于什么状态；
- 对用户或业务有什么影响；
- 需要用户做什么决定。

不要先介绍使用了哪些工具、执行了哪些内部步骤或调用了哪些技术组件。

### 4.2 专业术语随用随解释

能用日常业务语言表达时，直接使用业务语言。必须保留的专业名称采用“它解决什么问题（专业名称）”的方式说明。

示例：

- 原表达：`数据库迁移已完成，rollback 未触发。`
- 推荐表达：`现有数据已经安全转入新的存储方式，本次不需要恢复到旧版本。技术记录：database migration，rollback 未触发。`

不建立固定项目术语表。模型应根据当前任务、读者背景和上下文解释术语。

### 4.3 保持自然，不强套模板

简单结果用一两段话说明；存在多个选项、风险或步骤时再使用列表。不要在每次回复中机械添加“结果、影响、下一步”等标题。

句子应有明确主语和动作，避免连续使用名词缩写、被动语态和内部流程名称。

### 4.4 准确区分状态

必须区分：

- 计划做；
- 正在做；
- 已完成；
- 已通过自动检查；
- 已由用户或人工验收；
- 受阻或仍有风险。

不得把“代码已写完”表达成“功能已交付”，也不得把“等待验证”表达成“已经通过”。

### 4.5 技术细节作为依据保留

文件路径、命令、接口名、错误文本和精确标识保持原样。先解释这些信息对用户意味着什么，再把原始内容放在后面作为依据。

用户明确要求技术深度时，仍先提供一句简短结论，再展开实现和证据。

## 5. 回复前自检

发送回复前快速检查：

1. 第一段是否直接回答了用户当前最关心的问题；
2. 不懂代码的产品经理能否理解结果和影响；
3. 无法避免的专业术语是否已经解释；
4. 完成、验证、验收和受阻状态是否说准确；
5. 是否保留了必要的技术证据；
6. 表达是否自然，是否存在不必要的固定标题或过程汇报。

## 6. Skill 结构

```text
skills/speak-plainly/
├── SKILL.md
└── agents/
    └── openai.yaml
```

Skill 保持自包含，不增加脚本、术语库或项目专属参考文件。核心规则和一个高质量示例直接写入 `SKILL.md`。

## 7. 当前项目接入方式

WES 作为第一个使用项目，只在项目模型入口中增加强制引用：面向用户进行任务沟通时必须读取并遵循 `speak-plainly` Skill。

项目入口只负责触发，不复制 Skill 规则，避免通用规则与项目规则长期不一致。

## 8. 验收标准

Skill 完成后应满足：

- 通过 Skill 目录和 YAML 格式校验；
- 对进度汇报、问题分析、风险决策、技术交付四类场景均能生成自然的业务表达；
- 技术术语减少，但必要的名称、命令、路径和报错没有丢失或改错；
- 回复明确区分计划、完成、自动验证和人工验收；
- Skill 本体不包含 WES 或其他单一项目依赖；
- 当前 WES 的模型入口能够稳定触发该 Skill。

## 9. 与现有需求的关系

RP-046 只处理 WES 总看板页面文案。本 Skill 只处理模型面向用户的任务沟通，二者目标相关但范围不同，应分别记录并建立关联，不合并为同一需求。
