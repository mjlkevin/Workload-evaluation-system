## 2. 范围

### Batch B · 能力回复自然化（8h）

目标：`capability_discovery` 类提问从固定模板腔改为基于事实表的自然语言回复。

1. 新建能力事实表 `CAPABILITY_FACTS`（单一事实源）：以结构化条目列出工作台当前真实能力（业务问答、附件问答、报告生成 v1/v2、WES 数据查询、写操作需确认、Agent 工具 8 项），放在 `apps/api/src/services/ai/workbench-capability-facts.ts`。**事实必须与当前代码能力对齐，不得写未实现能力**。
2. `capability.handler.ts` 改为消费 `CAPABILITY_FACTS`，默认走模型辅助：用 kimi chat 将事实表改写成针对用户原话的自然回复（system prompt 约束：只许基于事实表作答，不许新增能力承诺）。
3. 降级路径：模型调用失败 / apiKey 缺失时，如实返回基于事实表的结构化回复，并在回复中标注「（以下为能力清单摘要）」，禁止静默假装模型生成。
4. `workbench-intent.service.ts` 的 `CAPABILITY_PATTERNS` 补充自然问法（如「你会干什么」「你能帮我干啥」「支持哪些操作」），保持正则单点，不得散落多处。

### Batch C · 回归加固（4h）

1. 新增 ≥9 类 dispatch/intent 用例（intent 层 ≥5、dispatch 层 ≥4）：能力提问命中、自然问法命中、能力+业务混合意图不误判、Batch A `unsupported_or_out_of_scope` 拦截行为不回退、模型辅助降级路径、报告显式请求不误入能力回复等。
2. 人工验收样本 6 条写入 `docs/agent-loop/testing/O10-BC-人工验收样本.md`（问法 / 期望行为 / 实际回填栏留空），由用户手工验收后回填 `testing.html`，执行会话不得代填实际结果。
