## 9. fake workflow 与故障注入点规范（RED 先行，强制）

按 Batch B 计划 §11–§12 执行，要点固定如下：

1. **fake workflow**：确定性步骤图（`fake_workbench_chat` / `fake-v1`），至少含
   `s1 input_commit → s3 tool_effect → s4 model_prepare → s5 model_generate → s6 final_commit`，
   检查点覆盖 `input_committed`、`tool_result_committed:<effectKey>`、`model_input_ready:<stepKey>`、
   `final_response_committed`；每个步骤暴露命名注入钩子（`failAfter:<stepKey>` / `failDuring:<stepKey>`），
   命中即模拟硬退出（Worker 实例不做清理直接终止，heartbeat 停止）。
2. **fake provider**：`AsyncIterable<StreamingChunk>`，支持按 attempt 区分脚本
   （attempt 1 中途抛错、attempt 2 完整输出）；输出文本带 attempt 标记供「无拼接」断言；全程无真实网络。
3. **四类崩溃注入点**（roadmap Step 2 原文四类，一一对应测试组）：
   - C1 输入后崩：`failAfter:s1` → 从 `input_committed` 恢复，用户消息不重复；
   - C2 工具成功后崩：`failAfter:s3` → effectKey 命中跳过副作用，副作用计数器 == 1；
   - C3 模型流中断：`failDuring:s5` → 丢弃 partial，从 `model_input_ready` 重做 s5，最终输出无拼接；
   - C4 投影前后崩：C4a「checkpoint 已提交、outbox 未投递」→ dedupe key 命中 `created=false`；
     C4b「Session 已写入、outbox 未标 published」→ Session 来源键命中，消息数不增。
4. **顺序**：先提交 C1/C2/C3/C4 的失败测试（RED 证据），再实现转 GREEN；handoff 保留每组
   RED→GREEN 的命令与输出摘要。
5. **时序参数**：lease 45s / heartbeat 15s / 扫描 10s / 3 次 / 退避 2/10/30s 为生产默认常量，
   全部可注入；单测断言默认常量精确等于上述口径，集成测试注入小值（lease ≥ 1000ms）。
6. **取消语义**：Batch B 无 HTTP cancel 接口；测试通过 repository 方法设置 `cancelRequestedAt`，
   断言 Worker 在安全边界停止、取消后零副作用、Coordinator 对失联 Run 取消优先。
