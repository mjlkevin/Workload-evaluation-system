### B1 变更

**问题**：`harness-boot.ts` 注入 workflow 的 dispatch 是抛错占位；`workbench-chat.workflow.ts` 内硬编码空 modelChat；flag-on 时任何 run 必失败或产出空回复。

**修复**：
1. `workbench-shared.ts` 新增 `buildWorkbenchChatDispatchInput()` 共享组装函数——复用同步链路同款口径：`resolveBusinessRole(user)` + `HOME_ROLE_PRESETS` + `normalizeKimiModelName()` + 真实 `modelChat`（`resolveActiveRequirementKimiApiKey` + 既有 kimi 客户端）。
2. `workbench-chat.handler.ts` 改为调用 `buildWorkbenchChatDispatchInput()`，同步路径行为逐字不变。
3. `workbench-chat.workflow.ts` 移除硬编码 `businessRole`/`roleLabel`/`model`/`modelChat`；dispatch 签名收敛为「workflow 只负责提取 content 与 run 身份，完整 dispatch 入参组装归 boot 注入侧」。
4. `harness-boot.ts` 增加 `createModelChat` 注入位；默认组装调用 `buildWorkbenchChatDispatchInput()` + `dispatchHomeWorkbenchTurn()`。
5. `harness-boot.test.ts` 新增 2 条测试：

### B2 变更

**问题**：`useChatMessages.js` 对 409 `SESSION_HAS_ACTIVE_RUN` 静默回退旧同步路径、无任何文案。

**修复**：
1. submitRun catch 分支显式区分三态：
   - `503` / `ASYNC_RUNS_DISABLED`：维持现状（缓存 + 回退同步路径）
   - `409` / `SESSION_HAS_ACTIVE_RUN`：呈现用户可见文案「该会话存在进行中的任务，请等待完成后再发送」，直接 return，不回退旧同步路径
   - 其他错误：维持现状（静默回退）
2. `run-submit.test.jsx` 新增 409 守护测试：旧同步路径零调用、文案可见。

### O2 人工验收指引

#### 预期行为

| 场景 | 预期 |
|---|---|
| flag on + 无活跃 run | 发送消息 → POST /ai-sessions/:id/runs → 202 → loading 保持 → SSE 事件到达 assistant 消息 |
| flag on + 同会话有活跃 run | 发送消息 → 409 → 文案「该会话存在进行中的任务，请等待完成后再发送」 |
| flag off | 发送消息 → 503 → 自动回退旧同步路径 `/ai/home-workbench/chat` |
| 离页/刷新/关页 | Run 继续执行（零 cancel 守护），回页后消息水合不丢不重 |
| 重登 | 同用户会话可见活跃 run 列表；新会话独立 |
| 明确停止 | 仅用户显式点击「停止」触发 cancel（Batch D 零 cancel 守护） |
| 逆序返回 | roadmap Task 5 Step 7 口径：多会话切换时消息归属正确 |

#### A/B 并行

- A 路径（flag on）：Run 提交 → worker 执行 → outbox → projector → Session
- B 路径（flag off 或 503）：旧同步路径 `/ai/home-workbench/chat` 逐字不变
- 503 探测后模块级缓存避免重复探测

- 附件场景：workflow 适配器当前纯文本问答先行；附件解析仍走旧同步路径
- 流式输出：当前非流式；roadmap Task 6 规划
- 监控栈：仅 SQL 快照取证，无常驻采集
