## 四类崩溃 RED→GREEN 证据

RED 形式说明：三个 harness 新测试文件在对应模块文件不存在时先行落盘（模块缺失即 import 失败的 RED）；dispatch 3 条取消测试做了真实 RED 运行。以下为逐类证据。

### C1 输入后崩（T3）

- 注入点：`faultInjector("s1", "afterStepCommit")` 抛 `HarnessFaultInjectedError`（模拟 `input_committed` 检查点落库后进程死亡）。
- 关键断言：恢复后 `status=completed`、`recoveryCount=1`；attempt#2 `resumeCheckpointId` 指向 `input_committed`；attempt#1 `orphaned`；`user_message` outbox 恰好 1 行；`recovery_started`/`recovery_completed` 事件各 1。
- 结果：✔ `T3 crash after input commit recovers from input_committed without duplicating the user message`（157ms）。

### C2 工具成功后崩（T4）

- 注入点：fake workflow 内部 `crashAfterToolEffectOnAttempt=1`，工具副作用已执行、`recordToolEffectOnce` 已落库、检查点未提交时崩溃。
- 关键断言：`toolExecutions=1`（跨 attempt 副作用恰好一次）；`harness_tool_events` 仅 1 行且 `effectKey=<runId>:s3:fake.tool:1`；最终 `completed`。
- 结果：✔ `T4 crash after tool effect reuses the effectKey and never repeats the side effect`（81ms）。

### C3 模型流中断（T5）

- 注入点：attempt#1 第 3 个 chunk 处抛故障（`modelFailAtChunkByAttempt={1:2}`）。
- 关键断言：最终输出来自且仅来自 attempt#2（`A2-full-1A2-full-2`，不含 `A1-part`）；`model_input_ready:s5` 检查点仅 1 行（restart_step 重放 s4 幂等去重）。
- 结果：✔ `T5 model stream interruption restarts the model step from model_input_ready without splicing text`（63ms）。

### C4a Worker 硬退出（T2b，真实时序）

- 注入点：`afterStepCommit` 故障后 Worker 静默退出（无任何内存清理），lease 自然过期。
- 关键断言：崩溃即刻 `findRunsWithExpiredActiveLease` 不含该 Run；真实 sleep 1200ms 后（leaseMs=1000）被扫描发现。
- 结果：✔ `T2b hard exit leaves the lease to expire naturally (real timing)`（1223ms）。

### C4b Session 已写入、outbox 未确认（T9b）

- 注入点：projector `faultInjector("afterAppend")` — sink 已追加 Session 消息、`markSessionOutboxPublished` 未执行时崩溃。
- 关键断言：崩溃后 outbox 行保持 `processing`；锁过期（lockMs=50，sleep 80ms）后健康投影仪重认领，来源键幂等吸收重放（`created=false`），Session 消息恰 1 条，行终态 `published`。
- 结果：✔ `T9b crash between session append and outbox ack replays without a duplicate message`（110ms）。

## 取消安全边界证据

- AbortSignal 传播：dispatch 层包装 `modelChat`（race）与 `modelChatStream`（逐 chunk 检查），handlers 零改动；预中止时模型零调用（断言 `modelCalled=false`）。
- Worker 取消（T11）：heartbeat 发现 `cancelRequestedAt` → abort → 模型流 chunk 循环中止；`cancel_requested`/`run_cancelled` 事件各 1；`final_response_committed` 检查点、`final_response` outbox、run output 均 0 行（取消后零写入）；attempt 终态 `cancelled`。
- 优雅停机（T2a）：`stop()` 后步骤安全边界 `releaseAttemptForShutdown`，Run 回 `queued`、attempt `cancelled`，后续 Worker 立即认领完成。
- lease 失效禁写（T1b）：外部 orphan 后 heartbeat 发现 → abort，步骤返回后边界拦截，检查点与 outbox 均 0 行。
- Coordinator 取消优先（T7b）：挂起取消的失联 Run 直接 `cancelled`，`recoveryCount` 保持 0（不消耗恢复预算）。
