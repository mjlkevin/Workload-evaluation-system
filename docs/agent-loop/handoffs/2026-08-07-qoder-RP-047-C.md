## Gate C 四条自证

### G1 API 契约与状态码全部有集成测试

- submit：202 冻结 envelope（message "任务已进入后台执行"、data {runId, sessionId, status: queued, eventCursor: 1}）；重复 submissionKey 返回同一 runId；缺 submissionKey / 空 content → 422；非 owner session → 404。
- 状态码矩阵逐条：cancel 已终态 409 RUN_ALREADY_TERMINAL；inputs 非 waiting 409 RUN_NOT_WAITING（且 422 校验先于状态检查）、waiting→queued 续跑；confirm 幂等（二次确认 200 且不重复写事件）；retry 仅 failed 允许、新 Run 带 retryOfRunId、**原 Run 行 JSON 快照逐字节零变更**。
- Session 删除：活跃 Run → 409 SESSION_HAS_ACTIVE_RUN 且不删；终态后删除 200；重命名不影响 Run。

### G2 owner 安全

- 全部端点 JWT 强制（无 token 401 测试）；跨 owner 一律 404：submit、list、snapshot、cancel、inputs、confirm、retry 逐端点断言。
- SSE 握手阶段 404（JSON），不建立事件流。
- 列表双用户数据互不可见（alice/bob 各见自己 1 条）。

### G3 SSE 回放与断线不取消

- `after` 游标回放：零丢失零重复（与 DB 事件全集逐条比对）。
- `Last-Event-ID` 头优先于 `after` 参数。
- 客户端中途 abort 后：run 状态不变（未被 cancel），重连以 Last-Event-ID 续传成功（1.2s 真实时序测试）。

### G4 flag 关闭与旧路径保护

- flag=false：submit → 503 ASYNC_RUNS_DISABLED；`/ai-runs/*` 全端点 503；Session 删除保持旧行为（无 409 检查，同步删除成功）。
- 旧路径未被删除：同步 AI chat、旧 Harness 域端点、`deleteAiSession` 缺省同步路径全部原样。
