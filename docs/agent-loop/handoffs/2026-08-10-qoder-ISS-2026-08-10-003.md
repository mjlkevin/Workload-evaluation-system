## 风险

- 时序竞争（方案 B 触发条件未出现）：`submitRun` 成功即后端 run 已落库（同步响应返回 runId 后才触发刷新），RED/GREEN 实跑未出现「刷新早于落库拉到空」；refreshUnifiedView 失败有 `.catch(() => {})` 静默降级，下次页签切回/重挂载仍会重拉，不阻塞发送链路。
- 并发重复刷新：发问后统一视图刷新会与 ISS-002 的新 runId 发现 effect 各触发一次 `notifyRunsChanged`（1.5s 节流兜底，最多 leading + trailing 各一次列表请求），不放大右下角请求量（该链路本工单零改动，既有节流测试守护）。
- 人工验收缺口：jsdom/MSW 已覆盖「2s 内刷新请求发出 + 角标出现 + 逐字帧呈现」契约，但工单 §9 验收口径（真实浏览器发问后顶栏 2s 内 ≥1、逐字及时开始、右下角不回退、flag 关闭逐字一致）仍需人工复测确认。
- 测试新增 import（`BackgroundRunProvider`）仅用于用例 3 渲染包裹，不改变被测生产代码路径。
