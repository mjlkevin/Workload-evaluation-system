## 2026-03-30：团队协同与角色化评估工作台

- **状态**：已交付（P0 已实现，`/api/v1/teams/*` 端点挂载，持久化 `config/teams/store.json`）
- **来源**：用户会话新增需求
- **优先级建议**：中高（建议纳入 V2 候选）

### 需求描述

系统需要建立一套团队功能，团队成员包含以下角色：

- `部门负责人`
- `实施顾问`
- `售前顾问`
- `销售顾问`

不同角色可共同组建团队并参与同一评估项目协同。

### 期望能力

- 角色化团队管理：支持团队创建、成员加入/移除、角色变更。
- 负责人全局视图：`部门负责人` 可查看本团队下所有评估方案的整体情况（进度/状态/责任人等）。
- 总方案协同：不同角色可围绕“总方案”进行评审、评论与协同处理。
- 过程留痕：评审与评论过程保留最小操作记录，便于追溯。

### 初步范围建议（后续评审）

- **P0（MVP）**：团队与成员模型、角色权限矩阵、团队方案列表可见性。
- **P1**：总方案评审流转、评论线程、@提醒与状态变更通知。
- **P2**：协同效率看板（待评审数量、响应时效、关闭率）与团队绩效视图。

## 2026-06-25：Kimi Provider 稳定性增强与流式输出

- **状态**：已分析 / 待规划
- **来源**：Kimi API 深度分析 + 用户主动要求
- **优先级建议**：P1
- **关联需求**：RP-027（Kimi API 模型升级与 Provider 成本优化）

### RP-028：Kimi Provider 稳定性增强：超时、重试与 Token 审计

基于 Kimi API 深度分析发现的三项 Provider 层稳定性缺口：

1. **超时上限**：MAX_TIMEOUT_MS=120s 对思考模型偏短，官方文档 stream=false 超时为 2 小时
2. **超时重试**：fetch 超时抛出的 ProviderError("timeout") 标记为 retryable=false，网络瞬断不会重试
3. **Token 审计**：parseSuccess/parseStream 均未提取 usage 字段，无法追踪 Token 消耗

建议与 RP-027 P6 技术债修复合并实施。

### RP-029：Kimi 流式输出与 WES 实时响应功能模块

用户主动要求启用 Kimi 流式输出，并设计 WES 功能模块匹配流式输出能力。当前 KimiProvider 已实现 streamChatCompletion，但所有业务接口均使用非流式 chatCompletion。

拆为三批实施：

1. **后端 SSE 接口层**：AI 工作台 /chat/stream、评估 /assessment/stream、文件解析 /parse/stream
2. **前端逐字渲染**：StreamRenderer 组件、思考过程折叠展示、中断/停止按钮
3. **流式场景完善**：中断/重试/错误处理、Token 消耗实时展示、流式工具调用
