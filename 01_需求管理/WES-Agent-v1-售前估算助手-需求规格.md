## 0. 摘要

WES Agent v1 是一个**引导式售前估算对话助手**。售前/商务用户提供客户材料，Agent 主动引导完成
「材料 → 结构化需求包 →（停顿确认）→ 实施初估人天」，产出可在对话中查看、导出 PDF，并由用户决定
是否存档纳入版本管理。

**一句话价值**：把售前「从一堆材料到一个能报的人天数」从数小时压缩到数分钟，且过程可控、结果可追溯。

**产品形态**：L2 内嵌 Copilot（半自主，人在环）+ 引导式流程（v1 聚焦售前主线，非开放式通用助手）。

---

## 1. 背景与定位

### 1.1 背景
WES 现有后端已 17/17 领域模块化，售前域具备「原始材料 → 需求包 → 初估包 → SOW」的现成 usecase。
v1 将其中**售前估算前半段**包装为对话式智能体，验证「自然语言驱动业务流程」的产品价值。

### 1.2 目标用户
**售前 / 商务**。最高频痛点是「快速从客户材料给出可报的人天数」，最看重响应速度，同时要求结果可控、可对外。

### 1.3 产品定位
> 引导式售前估算对话助手：用户丢材料 → Agent 引导走完到实施初估 → 可查看/导出/选择性归档。

---

## 2. 用户故事

| 编号 | 用户故事 |
|------|----------|
| US-1 | 作为售前，我想把客户的多份需求材料一次丢给助手，让它理出结构化需求清单，免去手动逐条录入。 |
| US-2 | 作为售前，我想在估算前先核对它理解的需求、补全它没把握的地方，避免估算建立在错误理解上。 |
| US-3 | 作为售前，我想快速拿到分模块的实施人天初估，以便立刻回应客户/领导。 |
| US-4 | 作为售前，我想把结果导出 PDF 发出去，直接对外沟通。 |
| US-5 | 作为售前，我想决定这次估算是「一次性」还是「要存档」；存档的下次能在其基础上迭代。 |

## 3. 主流程规格（引导式 5 阶段状态机）

```
[S0 开场]
  Agent 主动问候 + 说明能力 + 引导「请发客户材料」
        │ 用户上传/粘贴材料
        ▼
[S1 抽取中]  调 extract_requirement（多文件综合）
  对话流式显示进度：🔍 正在解析 N 份材料…
        │ 抽取完成
        ▼
[S2 需求包确认] ★人在环关键节点（确认理解）★
  工作区渲染结构化需求包（可编辑表格）
  低置信度 / 问询项 高亮标注，提示「请补全或跳过」
  用户：补全 / 修改 / 删除 / 确认
        │ 用户点「确认，开始估算」
        ▼
[S3 初估中]  调 estimate_implementation（已确认的需求包）
  对话流式显示：📊 正在估算…
        │ 估算完成
        ▼
[S4 结果呈现]
  工作区渲染分模块人天表 + 合计
  操作：[导出 PDF]  [存进系统]  [继续调整需求重估]
        │
        ▼
[S5 归档决策] ★写操作确认★
  Agent 询问：「要存进系统吗？」
    ├─ 存 → 确认后持久化 + 版本化；若关联已有方案 → 以上一版为基础升版
    └─ 不存 → 标记一次性评估，会话结束即消费完毕
```

### 3.1 状态机要点
- **仅两个强制人在环节点**：S2（确认理解）、S5（确认写库）。其余自动流转。
- 任意阶段用户可回退重来（改材料、改需求重估）。
- 主线不僵硬：用户中途提问，Agent 答后回到主线。

## 4. 功能需求清单（FR）

| 编号 | 功能 | 优先级 | 关联底层 usecase |
|------|------|--------|------------------|
| FR-1 | 多文件混合上传（文本粘贴 + Word/PDF/Excel），综合抽取 | P0 | ai/extractor |
| FR-2 | 结构化需求包抽取，含**置信度**与**问询项**标注 | P0 | ai/extractor、presales |
| FR-3 | 需求包确认面板：行级编辑（增/改/删）、补全缺失项、跳过 | P0 | presales |
| FR-4 | 实施初估：基于确认后需求包，出分模块人天 + 合计 | P0 | estimates.calculate |
| FR-5 | 结果工作区渲染（可编辑表格 + 合计） | P0 | （前端渲染） |
| FR-6 | 导出 PDF（复用现有导出能力） | P0 | exports |
| FR-7 | 归档决策：存/不存；存则持久化 + 版本化；**自动匹配已有方案**，命中则关联升版 | P0 | presales、versions |
| FR-8 | 引导式对话：开场引导、阶段提示、流式进度展示 | P0 | agent 编排层 |
| FR-9 | 流程回退：改材料 / 改需求 / 重估 | P1 | agent 编排层 |
| FR-11 | 售前成果看板：列出当前用户历史估算方案，支持查看/导出/续作，兼作续作关联入口 | P0 | presales、versions |

> **FR-10（会话内追问答疑）已砍出 v1**，移至 §13 延后清单。理由：v1 聚焦主线快速验证，答疑非核心路径。

---

## 5. 输入规格（FR-1 细化）

- **支持形式**：① 对话框粘贴文本；② 上传 Word/PDF；③ 上传 Excel；④ 一次多份混合，Agent 综合理解。
- **多文件混合为 v1 直接目标**（不分步）：用户可一次提交多份材料，Agent 综合抽取为单一需求包。
- **阈值**（实现时定具体值）：单文件 ≤ ~10MB、单次 ≤ ~5 份。
- **解析失败**：明确告知哪份失败、原因，不静默吞掉。

---

## 6. 产出与持久化规格（FR-6 / FR-7 细化）

- **展示**：S4 在工作区结构化呈现（非纯文字）。
- **导出 PDF**：任意时刻可导，内容 = 需求包 + 初估结果。
- **归档（写操作，需确认）**：
  - **存** → 调用现有售前 usecase 持久化需求包 + 初估，生成系统版本记录（带 ownerUserId）。
  - **续作识别（自动匹配）**：归档时系统自动尝试匹配已有方案：
    - **精准匹配**：若材料/用户提供了项目编码，按编码精准匹配。
    - **模糊匹配**：否则按「客户名 + 产品 + 关键词」匹配候选方案。
    - **命中** → 提示用户确认关联，确认后以上一版为基础升版（沿用现有 VCS）。
    - **未命中** → 返回「无匹配记录」，默认走新建。
    - 匹配结果仅作建议，最终关联/新建由用户确认（写操作不静默）。
  - **不存** → 不落库，会话结束即消费；已导出 PDF 副本由用户自行保管。

### 6.1 售前成果看板（FR-11 细化）

面向售前用户的成果展示页，**兼作续作关联的入口**（与 §6 自动匹配协同：看板即「已有方案」来源）。

- **列表**：展示当前用户（按 ownerUserId 隔离）已归档的估算方案，含客户名/产品/项目编码、初估人天合计、最近更新时间、版本号。
- **筛选/搜索**：按客户名、产品、项目编码、关键词检索。
- **行操作**：查看详情、导出 PDF、**基于此方案续作**（进入对话流程并预关联，归档时直接升版）。
- **基础统计**：估算方案总数、近期活动（v1 保持轻量，复杂统计后置）。
- **数据来源**：复用 presales + versions 现有 usecase，不新增持久化结构。

> 与「内部运营埋点」（§9）区分：本看板展示**业务产出成果**，面向售前用户；运营埋点面向系统健康，v1 仅埋点。

## 7. 异常与边界处理

| 场景 | 处理 |
|------|------|
| 材料完全无法解析 | 告知失败原因，引导换格式/补文本，不进入 S2 |
| 抽取结果大面积低置信度 | S2 显著提示「识别质量较低，请重点核对」，不阻断但警示 |
| 用户跳过必要字段 | 估算时对缺失项用保守默认，并在结果**标注「此处含假设」** |
| 估算工具失败 | 结构化报错 + 允许重试，不丢失已确认的需求包 |
| 用户权限不足 | 工具调用前 RBAC 拦截，明确提示「无权限」，不暴露内部细节 |
| 多轮循环异常 | 编排循环上限保护，超限优雅终止并保留已产出内容 |

---

## 8. 验收标准（v1「可用」定义）

- [ ] 售前能用「一句话 + 材料」在 S0→S4 内**无需手动跳页面**走完到初估。
- [ ] S2 能看到结构化需求包、能编辑，低置信项有标注。
- [ ] S5 能选择存/不存；存后下次能在该方案上迭代（版本 +1）。
- [ ] 全程读操作自动、写操作（存库）有确认。
- [ ] 典型材料（一份中等复杂度需求文档）端到端 ≤ 数分钟出初估。
- [ ] 多份材料混合提交，能综合抽取为单一需求包。
- [ ] 归档时自动匹配已有方案：命中给建议、未命中提示新建，关联后版本 +1。
- [ ] 成果看板能列出当前用户历史方案、可检索、可从中续作。
- [ ] 权限边界生效：用户只能在能力位范围内操作，数据按 ownerUserId 隔离。

## 9. 非功能需求（NFR）

| 类别 | 要求 |
|------|------|
| 权限 | 复用 RBAC；售前角色能力位决定可用工具；工具调用前必校验 |
| 数据隔离 | 沿用 ownerUserId，Agent 透传当前用户身份，不可跨用户读写 |
| 可观测（内部运营埋点） | 记录每次工具调用、token、回合数、耗时、成功/失败。**注意：这是内部运营埋点，区别于 FR-11 面向用户的「售前成果看板」**。v1 仅埋点入库，内部运营看板后置（v1.1）。 |
| 成本 | 编排循环上限 + 上下文复用，控制 token 消耗 |
| 模型 | 平台默认 Kimi（支持 function-calling）+ 预留 BYOK；限定支持 function-calling 的模型 |

## 10. v1 范围边界

### 做（IN）
售前材料 → 需求包 → 实施初估；**多文件混合输入**；需求包确认；PDF 导出；存/不存归档 + 版本化；
**归档自动匹配已有方案（编码精准 / 客户名+产品+关键词 模糊）**；**售前成果看板（兼续作入口）**；
引导式对话；权限与数据隔离。

### 不做（OUT）
- SOW 生成（链路边界外）
- 报价 / 成本测算（链路边界外）
- 外部对接（CRM / 邮件）
- 复杂多轮自主追问（v1 仅在 S2 停顿补全）
- 会话内追问答疑 FR-10（移至 §13，v1.1）
- 内部运营质量看板（v1 仅埋点，看板 v1.1）
- 多语言
- 其他角色（PM / 管理者）的专属流程

## 11. 关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 目标用户 | 售前 / 商务 | 最高频、流程化、价值清晰，v1 聚焦不失焦 |
| 链路边界 | 到实施初估为止 | 覆盖售前核心痛点「快速报数」，复杂度适中 |
| 交互节奏 | 需求包停顿确认 | 挡住「错误需求被拿去估算」，平衡速度与准确 |
| 产出落地 | 展示 + PDF + 选择性归档 | 兼顾一次性消费与可迭代存档两种真实诉求 |
| 缺失处理 | 标出让用户补 | 轻量、不多轮，契合停顿确认节奏 |
| 对话气质 | 引导式（非开放式） | 售前强流程化，引导式体感稳定、验收清晰；A 是 B 的子集，不走回头路 |
| 续作识别（v0.2 调整） | 自动匹配（编码精准/客户名+产品+关键词模糊），无匹配则新建 | 匹配成本不高且体验更好；命中仍由用户确认，不静默写库 |
| 成果看板（v0.2 新增） | 纳入 v1（FR-11），兼作续作关联入口 | 与续作自动匹配协同；面向用户的产出沉淀，区别于内部运营埋点 |
| 多文件（v0.2 确认） | v1 直接支持混合，不分步 | 用户明确要求；售前材料天然多源 |
| 会话内答疑（v0.2 砍） | FR-10 移至 v1.1 | v1 聚焦主线快速验证，答疑非核心路径 |
