## 需求描述

### 原始反馈
> 后续WES中需要团队协作系统，包含：
> 1. 项目团队成员围绕一个项目主线开展协作，能够看到项目主线中所有的上下文（表单/session/改动日志/评论等）
> 2. 项目创建人可以维护项目成员（添加/移除）

### 现状分析

WES 现有协作基础设施已实现 70%：

| 能力 | 现状 | 缺口 |
|---|---|---|
| 项目主线 | `ProjectEvaluationPlan` 持有全部子记录指针 | 未聚合为统一时间线 |
| 团队/成员/角色 | `team` 模块完整（P0 已交付） | 项目与团队关联单向 |
| 协同工作区 | `collab_workspaces` + `collab_messages` 全完整 | **前端零入口** |
| 改动审计 | `change_logs`（字段级）+ `change_submissions` | 未并入项目时间线 |
| 会话追溯 | `ai_sessions` 带 `linkedRecords.projectId` | owner 私有，成员无可见 |

**缺口本质**：不是模块级的功能空缺，而是**聚合层缺失** —— 五处事实散落无序，看不到项目完整上下文。

## 关键决策（已获用户确认）

1. **Session 可见性**  
   关联项目后自动对成员可见（不强制分享）+ deny 优先（已移除成员无回流）

2. **首期范围**  
   只读项目上下文 + 成员维护（不含通用评论/实时协同/跨域权限细化）

3. **存储策略**  
   PostgreSQL（新增 `project_members` 表）+ ProjectEvaluationPlan 扩字段（`teamId` / `visibility`）

4. **权限模型**  
   三通道（创建人 + 本团队 manager + ADMIN）+ 资源级守卫 + 能力位复用

## 风险预案

| 风险 | 等级 | 缓解方案 |
|---|---|---|
| N+1 查询延迟 | 中 | 5 适配器并发 + 指标阈值告警 → P3 升级事件表 |
| 跨存储一致性 | 中 | 软引用 + ops 脚本定期扫孤儿 |
| Session 隐私倒灌 | 高 | 上线前扫存量、owner 一次性确认窗口 |
| Manager 权限依赖 teamId | 低 | 项目创建引导绑定，面板标注权限限制 |
| 检出锁悬空 | 低 | 不自动解锁，成员面板告警 + ADMIN 手工强制 |
| 移除后权限漂移 | 低 | deny 优先判定，removed_at 冻结 |
