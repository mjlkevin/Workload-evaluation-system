# 系统管理统一化重构：调研、方案与实施记录

日期：2026-10-21
状态：推荐路线已确认 / 12页前端已实现 / 模板真实联调受阻 / 首批用户已确认，第二至四批目视待验收
范围：当前「系统管理」3 个分组、12 个子页；不包含基础管理、用户管理、独立 API 密钥页。
来源：ISS-2026-10-21-001 范围扩展；关联 RP-065、历史表格化基础 RP-053。

## 1. 建议结论

采用**统一列表骨架 + 统一详情/编辑弹窗 + 少量业务专用区域**。

所有可枚举对象默认以列表展示，让用户通过相同的位置完成查找、比较、查看与编辑。统一页面和交互规范，同时保留对象之间真实的字段、权限及生效方式差异。总体沿用 Datum 当前深色侧栏、浅灰页面、白色表面、品牌色主操作与既有字体/圆角/间距。

调研阶段只形成设计方案。用户确认后，第一批编码规则与工具策略已按第 11 节实施并获确认；第二批四页按第 12 节完成前端，其余六页仍为建议方案。未补做后端能力，实际配置未执行保存、生效、删除、密钥变更或外部模型验证。

## 2. 研究方法与边界

通过当前 IAB 已登录会话，逐页采集 1440×1000 实际界面；补查工具策略 760×1000，实测表格行高；检查现有路由、共享列表、Dialog、tokens 与对应页面代码。行业管理列表和模型配置列表用作系统内部视觉参考。

本次采集 15 张有效截图：12 个子页、1 个系统内部列表参照、1 个展开详情参照、1 个窄屏样本。加载中画面及模型配置初始回退画面已作废并重采。所有截图都在本次调研采集；assets 内保存与现场查看一致的 JPEG。API Key 仅保留页面原有遮罩，不记录完整凭据。

本地数据的数量不作为业务总量承诺。测试结果当前为空，因此其非空界面只从代码确认是卡片结构，未验证真实非空数据。未执行写入操作、错误注入、完整键盘巡检或完整无障碍审计；窄屏仅抽样工具策略，不能推断全部 12 页均存在同样问题。

## 4. 三个共同根问题

### R1：对象主视图不一致，比较相同信息需要反复移动视线

- 证据：01/02/03/04/10 卡片；05 折叠目录；06/09/11 表格；07 大表单混合列表。
- 影响：管理员每换一页都要重新寻找名称、状态和操作；批量浏览很慢。
- 设计修正：把可枚举对象统一到同一列表骨架；诊断类保留任务输入区域，其结果列表也遵循同一列、行、空态规范。
- 确定性 owner：现有 PageShell/两级导航保持；共享列表能力从 ListPage 中复用，形成可嵌入系统页的列表主体；具体字段由各子页定义。

### R2：未区分摘要与详情，表格也会变成高大的卡片

- 证据：09 工具策略 12 列、数据行约 218px；11 首尾文本与两组日期并列；15 窄屏下主要操作需要横向寻找。
- 影响：重要状态难以同屏比较，阅读路径被长文本和编辑控件打断。
- 设计修正：默认约 6–7 列（含操作），摘要最多两行，标准行高 36px，确需双行的记录按 52–64px；角色最多展示 2 个 +「另 N 个」，完整信息放详情；不把整组编辑控件常驻在行中。
- 确定性 owner：列表列渲染、密度与溢出由共享主体负责；长字段内容与编辑表单由对象详情/Dialog 负责。

### R3：浏览、编辑和配置生效混在一起，操作对象与保存结果难以判断

- 证据：01 顶部和卡片中重复配置/生效/禁用；07 浏览前先出现可编辑的大表单；09 浏览同时可以修改角色与策略，并另有本地/草稿/生效状态。
- 影响：用户难以判断修改了哪条、是否保存、是否已经生效。
- 设计修正：行操作负责明确单条对象；页面操作负责新增/刷新等全局任务；编辑进入统一 Dialog；有草稿机制的对象保留独立的保存草稿与生效配置状态条，立即生效的业务动作仍按原业务执行并明确提示。
- 确定性 owner：共享工具栏与详情/编辑容器约束操作位置；每个领域的 Hook/API 继续负责实际保存、生效与权限，不在 UI 组件里复制业务规则。

## 5. 三种重构路线比较

| 路线 | 适用性与代价 | 判断 |
|---|---|---|
| A：全部改为一张扁平表格 | 形式最一致，但复杂参数、知识库连接、诊断输入会挤进表格，工具策略问题会重复 | 不采用 |
| **B：统一列表 + 统一详情/编辑 Dialog + 专用任务区** | 浏览/比较/操作统一；数据结构与领域规则保留差异；能够沿用现有组件和 tokens，逐页迁移 | **推荐** |
| C：统一左侧列表、右侧常驻详情 | 适合频繁逐条对照，但占用宽度，760px 需另做布局，且改变全模块操作方式 | 本轮不采用；将来可针对高频审计单独评估 |

## 6. 推荐方案的页面与交互规范

### 6.1 一个稳定的页面结构

沿用现有页面标题、说明与两级分类导航，下面固定为：

1. 列表工具栏：左侧对象数量与范围；中部搜索/状态/类型筛选；右侧新增、刷新或该页确有的主操作。
2. 配置状态条：只有具备草稿/生效双轨的页面显示；只占一行，复杂差异进入详情。
3. 主列表：对象名称、关键属性、状态、操作的位置固定；具体列按领域变化。
4. 页脚：共 N 条 / 当前范围 / 每页 10 条 / 分页；少量固定配置可不分多页，但保留总数。

页面只使用已有层级，不为每个小区块再加一层路由或卡片墙。模型配置继续保留供应商和场景绑定两个逻辑表，避免为了「一页一表」把两种对象硬拼在一起。

### 6.2 一致的详情与编辑入口

- 名称链接或明确的「查看」打开详情 Dialog；不把双击或整行点击作为唯一入口。复选框仅用于已有批量业务操作，不默认出现在所有对象表。
- Dialog 头部统一显示对象名称与状态；内容分基本信息、规则/参数、关联信息、来源/审计。没有实际字段的区块不出现。
- 行级编辑在 Dialog 内完成；保留顶部空白区拖拽、初始焦点、Esc、焦点返回和未保存保护。
- 统一出口是同一 Dialog 组件与相同命名，不并行引入抽屉、第二组件库或页面内临时编辑区。
- 状态机的图/流转表和会话摘要放在详情内部；复杂只读内容在 Dialog 内滚动，不把主列表撑高。

### 6.3 保存、草稿和生效

| 情况 | 页面应怎样表达 |
|---|---|
| 无未保存修改 | 显示当前生效版本或已有状态；无意义的保存按钮禁用 |
| 本地修改尚未保存 | 「有未保存修改」；Dialog 动作用「应用修改」等明确文案，避免误报已生效 |
| 已保存草稿，未生效 | 「草稿已保存 · 尚未生效」；保留「生效配置」入口和差异查看 |
| 生效失败 | 明确显示失败；保留草稿和输入，不更新为成功标签 |
| 记忆确认、归档等现有业务动作 | 按当前接口语义执行，不强加全局草稿流程 |

供应商密钥的设置/清除是独立凭据操作，应单独说明结果，不能把它模糊包装成「和模型草稿一起生效」。状态显示区分启用状态、验证状态、发布状态，不用一个「已生效」覆盖所有含义。

### 6.4 总体风格保持一致

- 沿用深色侧栏、浅灰背景、白色列表表面、品牌色选中/主操作、绿/黄/红语义状态。
- 沿用 tokens 的字体、字号层级、36px 控件高度与 6/10/14px 圆角，不新增色盘、大阴影或另一套导航。
- 表头浅底、正文轻分隔、状态文字+标签、数值右对齐；不以大图标或大 KPI 卡片抢占浏览区域。
- 操作最多常显 1–2 项；低频操作进入「更多」。删除、禁用、清除密钥明确对象与后果，并沿用原有确认机制。
- 控件旁长说明进入现有 Tooltip 或详情；错误、未保存状态与权限原因留在操作附近。

### 6.5 响应式、加载和权限

1440px 下主要字段与操作应在一屏宽度内可用；760px 下先隐藏低优先级列，保留名称、状态、核心属性和查看。完整字段进入详情；确需横向滚动的专业表格应有可见滚动/键盘入口，不能靠页面裁切隐藏内容。

全部子页使用同规格加载、错误+重试、无数据与无匹配结果。不能用 0 冒充尚未加载，不能把默认演示数据无标识地当成服务端配置。搜索/筛选状态在返回详情后保留；页面内未保存修改离开时提示，不丢输入。

可访问性验收覆盖搜索标签、表格名称/表头、行操作可读名称、焦点可见、Dialog 键盘路径和状态播报。该要求是未来验收目标，本轮不声明全部满足。

## 10. 验收方向（全模块方案；首批验证见第 11 节）

浏览体验：十二个入口均能在同一位置找到对象、状态、搜索和操作；可枚举对象默认是列表；长信息可查看全量。
