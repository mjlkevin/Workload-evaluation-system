01 / Diagnose

当前前端的几个问题

读取 app/globals.css、app-sidebar.tsx、Dashboard / Login 等页面后的观察。

① 配色调性偏「灰 + 青绿点缀」

--accent: #0d9488 · --primary: #1a1a1a

主色直接用纯黑（#1a1a1a），点缀用 Tailwind teal-600；选中态、焦点态、品牌识别都借这一个绿色，缺少层次。整页给人「v0/shadcn 默认模板」的印象。

② Kimi 紫色按钮独立于体系

.wes-kimi-help-btn · 6 段紫色渐变 + 流光动画

渐变按钮非常醒目，但与主色（青绿）+ 主背景（中性灰）完全割裂；它实际上承担了「AI 智能能力」这个核心卖点，应升格为系统级语言而不是孤岛。

③ 数据密度高但视觉节奏弱

Dashboard：4 KPI + 长表 + ER 图 + 最近动态

所有卡片都是 1 像素灰边 + 0.75rem 圆角 + 半透明卡背景，密度高时阅读疲劳；状态徽标（进行中/待评审/已检入）颜色偏类似，难以"扫读"。

④ 版本/检出语义未被设计放大

VersionVcsToolbar · 7 个 icon-only 按钮

版本控制是 WES 的差异化能力（Check-out / Check-in / Promote / Force-Unlock），但目前只是工具栏 icon 排版，新人完全看不出是 Git 式的强语义。

⑤ 多角色入口缺位

现有侧栏 8 项 · 后端已支持 4 大新角色

侧栏全部按"功能"组织（评估/资源/开发/WBS）；但业务真正需要的是按"角色"组织（售前/PM/PMO/销售/开发顾问），新模块若继续追加只会更挤。

⑥ 静态、缺乏过渡反馈

仅 hover 颜色变化，无微动画

检出/检入/升版/重算这类"会改变状态"的操作，反馈仍依赖文字提示。希望在不打扰的前提下，加入 ≤200ms 的 motion 反馈和占用动画（数字滚动、版本徽标切换）。

03 / Components

核心控件的搭配优化

基于上面的配色，对 WES 高频控件给出新规范；保持 Tailwind + shadcn 改动量最小。

按钮体系 Button

主按钮改为深空蓝（带 inset 高光 + 软阴影）；将原 Kimi 紫色渐变收编为 Accent 智能按钮，仅用于 AI 抽取、AI 重算、生成 SOW 等"会调用 LLM"的语义。

输入控件 Input · Search

聚焦态加 4px 蓝色软光晕；默认状态边框降一档（line-2）让密集表单不刺眼。搜索框图标内嵌 SVG，避免依赖 lucide。

状态徽标 · 强语义化 Badge

5 种核心状态各自有独立色相（不再都用 outline 灰边），并统一加左侧色点；扫读距离 ≥3m 也能区分。
