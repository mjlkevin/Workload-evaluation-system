## 1. 前置条件

### 1.1 软件要求

| 软件 | 最低版本 | 说明 |
|------|----------|------|
| Docker | 24.0+ | 含 Docker Compose V2 |
| Node.js | 20.x | 仅开发模式需要 |
| Git | 2.40+ | 拉取代码 |
| curl | 任意 | 冒烟验证 |

### 1.2 硬件要求

| 环境 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| 本地开发 | 2 核 | 4GB | 10GB |
| 生产 Beta | 2C4G 起 | 4GB | 60GB SSD |

### 1.3 网络要求

| 端口 | 服务 | 用途 |
|------|------|------|
| 3000 | API | 后端 API 服务 |
| 5432 | PostgreSQL | 数据库（仅开发/编排暴露） |

> **注意**：生产环境只暴露 80/443（Nginx 反向代理），3000 端口不对外开放。

## 2. 本地开发启动

### 2.1 一键启动（推荐）

```bash
# 1. 克隆仓库
git clone <repo-url> && cd Workload-evaluation-system

# 2. 准备环境变量
cp .env.example .env
# 编辑 .env，至少更换 JWT_SECRET 为随机值：
# JWT_SECRET=$(openssl rand -hex 32)  # 生产环境必换

# 3. 一键启动
docker compose up --build
```

启动后访问：
- API 健康检查：`curl http://localhost:3000/api/v1/health`
- 预期返回：`{"code":0,"message":"ok","data":{"service":"Workload Evaluation API","status":"ok"}}`

### 2.2 前端启动（独立开发模式）

API 通过 Docker 运行在 3000 端口后，前端可独立启动：

```bash
cd ui/V0_SAAS
cp .env.local.example .env.local  # 如有
npm install
npm run dev
```

前端访问 `http://localhost:3001`，会自动将 `/api/*` 请求代理到 `http://localhost:3000`。

### 2.3 停止与清理

```bash
# 停止所有容器
docker compose down

# 停止并删除数据卷（会丢失所有数据！）
docker compose down -v

# 查看日志
docker compose logs -f api
docker compose logs -f db
```

## 3. 生产部署步骤

### 3.1 服务器初始化

```bash
# Ubuntu 22.04 示例
ssh ubuntu@<server-ip>

# 安装 Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 重新登录后生效

# 验证
docker compose version
```

### 3.2 部署应用

```bash
# 1. 拉取代码
git clone <repo-url> && cd Workload-evaluation-system
git checkout main

# 2. 准备生产 .env
cp .env.example .env
# 编辑 .env，填入以下生产值

# 3. 启动服务
docker compose up -d --build

# 4. 验证
curl -f http://localhost:3000/api/v1/health
docker compose ps
```

### 3.3 配置反向代理（Nginx）

```nginx
# /etc/nginx/sites-available/workload-eval.conf
server {
    listen 80;
    server_name your-domain.com;

    location /api/ {
        proxy_pass http://127.0.0.1:3000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/workload-eval.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# HTTPS（Let's Encrypt）
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 3.4 数据备份

```bash
# 每日自动备份 config/ 目录（已在 .env 中配置）
npm run ops:backup:config

# 数据库备份（PostgreSQL）
docker exec workload-db pg_dump -U workload workload_eval > backup-$(date +%Y%m%d).sql

# crontab 示例
# 10 2 * * * cd /path/to/Workload-evaluation-system && npm run ops:backup:config
# 20 2 * * * cd /path/to/Workload-evaluation-system && npm run ops:check:config
```

## 4. 环境变量清单

### 4.1 必填项

| 变量 | 默认值 | 说明 | 示例 |
|------|--------|------|------|
| `JWT_SECRET` | `change-me-to-a-strong-random-string` | JWT 签名密钥，**生产必换** | `$(openssl rand -hex 32)` |
| `KIMI_API_KEY` | `sk-...` | Kimi AI API 密钥 | `sk-xxxxxxxxx` |

### 4.2 数据库（Docker 编排时使用）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `POSTGRES_USER` | `workload` | 数据库用户名 |
| `POSTGRES_PASSWORD` | `workload` | 数据库密码，**生产必换** |
| `POSTGRES_DB` | `workload_eval` | 数据库名 |
| `DATABASE_URL` | `postgres://workload:workload@db:5432/workload_eval` | 数据库连接串 |

### 4.3 可选项

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3000` | API 监听端口 |
| `JWT_EXPIRES_IN` | `8h` | JWT 过期时间 |
| `KIMI_MODEL` | `kimi-k2.5` | Kimi 模型名称 |
| `KIMI_API_BASE_URL` | `https://api.moonshot.cn/v1` | Kimi API 地址 |
| `CONFIG_INTEGRITY_ON_STARTUP` | `true` | 启动时数据完整性检查 |
| `DATABASE_POOL_MAX` | `10` | 数据库连接池最大连接数 |

### 4.4 安全提醒

- `JWT_SECRET` 和 `POSTGRES_PASSWORD` 必须使用强随机值
- 不要将 `.env` 提交到 Git
- API 密钥通过环境变量注入，不写入镜像层

## 5. 常见故障排查

### 5.1 端口冲突

```bash
# 检查端口占用
lsof -i :3000
lsof -i :5432

# 解决方案：修改 .env 中 PORT 值，并同步修改 docker-compose.yml 中端口映射
```

### 5.2 容器启动失败

```bash
# 查看容器状态
docker compose ps

# 查看日志
docker compose logs api
docker compose logs db

# 常见原因：
# - .env 文件缺失或 JWT_SECRET 未设置
# - PostgreSQL 连接失败（检查 DATABASE_URL）
# - 端口被其他进程占用
```

### 5.3 数据库连接问题

```bash
# 测试数据库连接
docker exec workload-db pg_isready -U workload -d workload_eval

# 查看数据库日志
docker compose logs -f db
```

### 5.4 前端无法连接 API

```bash
# 确认 API 健康
curl -f http://localhost:3000/api/v1/health

# 确认前端代理配置
cat ui/V0_SAAS/next.config.mjs | grep WORKLOAD_API_ORIGIN

# 开发模式：确保 .env.local 中 NEXT_PUBLIC_API_URL 指向正确地址
```

### 5.5 数据完整性检查

```bash
# 手工校验
npm run ops:check:config

# 修复模式
npm run ops:check:config:repair

# 查看修复日志
tail -f logs/data-anomaly-repair.log
```
