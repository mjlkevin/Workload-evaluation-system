## 一、版本文档状态机（单独成体系，VCS 语义）

版本文档（评估/需求/资源/开发/总方案）由 **三条正交状态轴 + 六个动作守卫 + 版本号递增规则** 构成，
权威来源：`apps/api/src/types/index.ts` L254-261 + `modules/versions/versions.usecase.ts`。

### 1.1 三轴

| 轴 | 状态集 | 初始态 | 说明 |
|---|---|---|---|
| 文档主状态 `status` | draft / reviewed / published / archived（可恢复） | draft | PATCH `/api/v1/versions/:recordId/status` 支持任意合法值间双向更新（含 archived 恢复）；需 estimates:write、admin/operator 与本人 owner；非法值 40001；首次进入 reviewed/published 补记 reviewedAt/reviewedBy |
| 编辑锁 `checkoutStatus` | checked_in（只读）/ checked_out（排他编辑） | checked_in | 六动作驱动，见 1.2 |
| 版本文档审核态 `versionDocStatus` | drafting / reviewed | drafting | drafting 可检出可升版；reviewed 为只读闸门。**当前代码唯一写入值是 drafting，drafting→reviewed 暂无现行端点（未实现）** |

### 1.2 六动作守卫（检出状态轴）

| 动作 | 端点 | 流转 | 守卫（不满足即拒绝） |
|---|---|---|---|
| checkout 检出 | POST `/versions/:id/checkout` | checked_in → checked_out | 非历史归档（40902）；`versionDocStatus=reviewed` 只读需先升版（40902）；未被他人占用——并发 CAS 恰一赢家 |
| checkin 检入 | POST `/versions/:id/checkin` | checked_out → checked_in | 须检出态且**检入人=检出人**（40301/40902）；行锁事务内版本号 minor+1（A1→A2） |
| save-draft 存草稿 | PATCH `/versions/:id/save-draft` | checked_out → checked_out | 须检出态且检出人本人；只更新 payload，**不递增版本号、不检入** |
| undo-checkout 撤销检出 | POST `/versions/:id/undo-checkout` | checked_out → checked_in | 仅检出人；payload 回滚到检出时 `lastCheckinPayload` 快照 |
| promote 升版 | POST `/versions/:id/promote` | checked_in → checked_out（新版本直接处于已检出态，旧版进归档） | 须 checked_in + `versionDocStatus=drafting` + 非历史归档；编码字母+1 数字归 1（A3→B1） |
| force-unlock 强制解锁 | PATCH `/versions/:id/force-unlock` | checked_out → checked_in | **仅 admin（system:manage）**，用于持有人缺位时的锁治理 |

### 1.3 版本号递增规则（不变式）

- checked_in 只读、checked_out 可编辑；状态只能由上述动作改变。
- 历史归档版本（isHistoricalArchive）不可检出、不可升版。
- 检入递增自然数（A1→A2）；升版字母+1 且自然数归 1（A3→B1，检入后 B1→B2）；`baseCode` 固定为首次检入前编码。
- 升版后状态以后端返回为准（新版本记录独立 id，旧版进归档）。

## 二、业务对象状态机（20 类）

每对象给出：状态集（★=初始态，⛔=终态）、已落地流转、未实现流转、不变式。
「未实现」= 口径已定义但后端暂无写入路径，如实标注。

### 2.1 项目 `project`
- 源：`modules/project-evaluations/project-evaluations.types.ts`（VALID_PROJECT_STATUSES）
- 状态：★draft 草稿 / active 进行中（枚举预留）/ reviewing 待评审 / published 已发布⛔ / archived 已归档⛔
- 流转：draft→reviewing ✅（确认 AI 实施评估草稿 POST `/project-evaluations/assessment-drafts/:assessmentId/confirm`，人工确认才流转）；draft→active ❌；reviewing→published ❌；published→archived ❌
- 不变式：非法 projectStatus 仓储层兜底为 draft；按 owner 隔离；容器落 version_records（recordKind=project_evaluation）

### 2.2 AI 会话 `ai_session`
- 源：`modules/ai-sessions/ai-sessions.usecase.ts`（VALID_STATUSES，9 态）
- 状态：★temporary_chat / rough_estimate / project_discovery / requirement_drafting / assessment_drafting / standard_review / standard_drafting / linked_record / archived
- 初态：`createAiSession` 创建时可指定合法 status（非法兜底 temporary_chat）。
- 流转：temporary_chat→linked_record、linked_record→archived 均未实现；POST `/api/v1/sessions/:sessionId/events` 只追加消息、附件、产物和待办，不更新会话 status。
- 不变式：现行仓储无既有会话阶段更新入口，archived 标签不代表已实现归档动作；域二值 business_evaluation / standard_governance

### 2.3 AI 会话产物 `ai_artifact`
- 状态：★generated / accepted / linked / superseded / discarded
- 初态：会话事件追加新产物时可指定五态白名单内的 status（非法兜底 generated）。
- 流转：既有产物 generated→accepted→linked 均未实现；仓储仅拼接产物数组，相同 artifactId 追加也不替换旧项。
- 不变式：追加产物初态与更新既有产物状态是不同能力；现行仓储无既有产物状态更新入口

### 2.4 Harness Run `harness_run`（AI 异步任务）
- 源：`modules/harness/harness.types.ts + harness-runtime.types.ts`
- 状态：★queued / running / waiting / recovering / cancelling（以上活动态）；completed⛔ / failed⛔ / cancelled⛔（终态）
- 流转：queued→running（worker claim+租约）；running→waiting（待确认动作）；running→completed/failed；running→cancelling→cancelled（异步两段式取消，不做瞬断）；running→recovering（租约过期接管）
- 不变式：活动/终态集合以 ACTIVE/TERMINAL 常量为准；已终态再操作返回 RUN_ALREADY_TERMINAL

### 2.5 Harness Attempt `harness_attempt`
- 状态：★claimed / running / succeeded⛔ / failed⛔ / orphaned⛔ / cancelled⛔
- 不变式：attemptNo 递增；orphaned 是失联判定而非业务失败

### 2.6 Harness 待确认动作 `harness_action`
- 状态：★pending / confirmed / executed⛔ / cancelled⛔ / failed⛔
- 流转：pending→confirmed（用户确认，run 由 waiting 回 running）；pending→cancelled（取消级联）；confirmed→executed/failed（幂等键防重复）
- 不变式：写动作只返回待确认动作，AI 不自动执行（AGENTS.md AI 工作台边界）

### 2.7 Harness 输出 `harness_output`
- 状态：★partial / final
- 不变式：partial→final 是发布语义，不是执行状态

### 2.8 人工测试结果 `manual_test_result`
- 状态：★passed / failed / blocked / skipped（无步进流转）
- 不变式：登记即结论；metadata 保留账号、截图等佐证

### 2.9 变更提交 `change_submission`
- 源：`db/schema/change_submissions.ts + routes/change.routes.ts`
- 状态：★submitted / reviewed（预留）/ merged⛔ / rejected⛔
- 流转：submitted→merged（POST `/api/v1/change/change-submissions/:id/merge`，需 man-day:adjust）；submitted→rejected（POST `/api/v1/change/change-submissions/:id/reject`，需 man-day:adjust 或 deliverable:reject）✅；submitted→reviewed ❌（无现行写入端点）
- 不变式：父实体三类 opportunity_brief / requirement_pack / assessment_version

### 2.10 开发评估 `dev_assessment`
- 源：`modules/dev-assessment/`
- 状态：★draft / in_progress / review_pending / confirmed / merged⛔
- 流转：draft→in_progress（AI 结果落库）→review_pending→confirmed→merged，PATCH 白名单校验（非法值忽略字段）
- 不变式：contractMode（embedded/separate）与状态机正交

### 2.11 售前简报 `sales_briefing`
- 源：`modules/sales-briefing/sales-briefing.controller.ts + sales-briefing.repository.ts`
- 状态：★open / converted / abandoned（均可改回其他合法状态）
- 流转：PATCH `/api/v1/sales/briefs/:id` 支持三态间任意双向更新，包括 converted/abandoned→open；需 estimates:create；非法 status 忽略该字段，无前态限制。
- 不变式：仅有状态值域约束；linkedRequirementPackId 为独立可选字段，转化不强制携带

### 2.12 协作问题 `collab_question`
- 源：`modules/collab/collab.repository.ts`
- 状态：★open / resolved / closed（可重开）
- 流转：PATCH `/api/v1/collab/messages/:messageId` 支持三态间任意双向更新，包括 closed→open；需 evidence:write；非法 status 忽略该字段，无前态限制；question 类默认 open，非 question 创建即 resolved
- 不变式：工作空间统计只数 question 且 status=open

### 2.13 团队评审 `team_review`
- 源：`modules/team/team.usecase.ts + routes/team.routes.ts`
- 状态：★open / closed（可重开）
- 流转：open↔closed（PATCH `/api/v1/teams/:teamId/reviews/:reviewId/status`）；需 deliverable:review 或 deliverable:reject 且为团队 manager；非法 status 返回 42201，无前态限制。
- 不变式：持久化执行版本冲突检查（40909）；关闭后可用同一接口重开

### 2.14 知识库条目 `knowledge_entry`
- 源：`modules/knowledge/knowledge-pg.repository.ts + routes/knowledge.routes.ts`
- 状态：draft / ★active（创建默认态）/ archived⛔
- 流转：仓储 `KnowledgePgRepository.update(id, { status })` 支持 draft↔active，当前无 HTTP 更新端点；draft/active→archived 由 POST `/api/v1/knowledge/entries/:entryId/archive` 实现（需 system:manage）。
- 不变式：archived 条目不可 update（KNOWLEDGE_ENTRY_ARCHIVED），可重复 archive；draft/active 无单向步进限制；检索语料只含非 archived 条目（BM25）

### 2.15 跨会话记忆 `memory`（原子/场景）
- 源：`modules/memory/memory.controller.ts + memory.usecase.ts + memory.repository.ts`
- 状态：★draft / active / archived（可恢复）
- 流转：POST `/api/v1/memory/atoms/confirm`、`/api/v1/memory/scenes/confirm` 实现 draft/archived→active；POST `/api/v1/memory/atoms/archive`、`/api/v1/memory/scenes/archive` 实现 draft/active→archived；均已实现，同目标状态可重复执行。
- 守卫：JWT 身份派生 ownerUserId；请求体 memoryIds 校验（非法 INVALID_BODY/422）；仓储仅按 id + ownerUserId 隔离，无前态条件。
- 不变式：原子与场景共用值域；confidence 与状态正交（默认 80）

### 2.16 用户账号 `user_account`
- 状态：★active / disabled（可恢复）
- 流转：双向（PATCH `/auth/users/:userId/status`）；守卫：不能停用自己（cannot_disable_self）、sub_admin 不能停 admin
- 不变式：角色三值 admin|sub_admin|user；businessRole 与账号状态正交

### 2.17 一次性令牌 `runtime_token`（邀请码/重置令牌）
- 状态：★active / used⛔
- 流转：active→used（核销，一次性不可复用；重置 token 另有 expiresAt）
- 不变式：令牌禁止硬删，历史留档

### 2.18 版本号编码规则 `version_code_rule`
- 源：`types/index.ts + modules/system/system.usecase.ts` L204-227
- 状态：★draft / active / disabled
- 流转：draft→active（activate，同时写 effectiveAt）；active→disabled（disable）；disabled→draft（一经编辑自动回 draft）
- 不变式：同 moduleKey 同一时刻仅一条 active

### 2.19 主数据 `master_data`（行业/产品/SKU/模块/标准人天）
- 源：`db/schema/industry.ts + product_master_data.ts`
- 状态：★active / inactive
- 流转：双向（setStatus，仅接受 active|inactive，其余 40001）
- 不变式：**只停用、禁止硬删**（外键 onDelete: restrict）；TS 枚举约束不建 PG CHECK

### 2.20 WBS 任务 `wbs_task`
- 源：`02_产品设计/产品闭环收敛清单-V1.md §1`
- 状态：★未开始 / 进行中 / 已完成⛔
- 流转：均未实现（MVP 为只读派生视图，任务编辑持久化属二轮需求）
- 不变式：当前展示状态由派生逻辑决定

## 三、治理机制

| 机制 | 位置 | 作用 |
|---|---|---|
| 目录真源 | `apps/api/src/modules/system/state-machines.catalog.ts` | 状态轴/流转/守卫/不变式的唯一登记处 |
| 只读接口 | `GET /api/v1/system/state-machines`（requireCapability("system:manage") + requireAdmin） | 前端可视化数据源；静态代码事实，不落库 |
| 防漂移测试 | `state-machines.catalog.test.ts`（已登记 `npm run test:modules`） | ①schema 完整性（from/to 闭合、initial∈statuses、trigger/guard 非空）；②目录状态集与源码运行时枚举（VALID_PROJECT_STATUSES、VALID_STATUSES、HARNESS_* 、MASTER_DATA_STATUSES 等）逐字比对 |
| 能力契约测试 | `state-machines.capabilities.drift.test.ts`（已登记 `npm run test:modules`） | 仅导入静态目录，核对可恢复状态、已实现流转与真实端点，不加载 DB；源码能力变化时须一并复核契约 |
| 可视化页 | 系统管理 → 规则与标准 → 状态机规则（`/system/rules/state-machines`） | 只读展示，无任何状态修改入口 |

**变更纪律**：修改任何对象的状态枚举或转换守卫时，必须同步更新目录，否则防漂移测试先红。
「从界面编辑状态机规则」不在设计范围内——规则变更只能通过改代码完成。
