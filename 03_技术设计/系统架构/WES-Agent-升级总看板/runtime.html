Section 01

核心判断

Qoder 带来的核心启发不是三栏界面，而是把每次对话变成可管理的 AI 任务。WES 不会在上传文件后强制进入固定报告流程，而是根据用户当前意图选择业务问答、附件问答、报告生成、WES 数据查询或写入确认。

业务定义一次任务运行（Harness Run）代表一项可追溯的 AI 业务任务。对话负责输入和澄清，意图识别器（Intent Router）选择处理路径，任务执行过程负责记录任务归属、使用的文件和知识、当前阶段、任务产物（Artifact）、人工确认动作和最终交付结果。
RP-047 Batch A2 已集成业务主线A2 已证明历史数据可升级，Run/首事件原子提交，事件、checkpoint 和 output 并发幂等；R1 关闭了 Date/Map 等普通对象边界与 handoff 记录缺口。Codex 在最终组合分支复跑 Testcontainers Harness 95/95、modules 227/227、AI 190/190、integration 1/1、Web 206/206、API/Web build 与安全扫描，全部通过。当前只交付持久运行数据底座，不代表 Worker、异步 API、AI Session 投影或前端恢复能力已经交付。
不是聊天增强

对话只是入口

用户上传文件、补充说明、业务追问和选择下一步动作，都应进入可追溯的任务记录。

不是自动落库

任务过程控制边界

AI 可以生成报告、草稿和建议动作；正式业务仍必须经过传统系统人工确认。

不是固定流水线

意图触发工作流

附件提供上下文，是否生成报告、查询项目或只回答问题，由用户当前意图决定。

Section 02

Qoder 到 WES 的映射

Qoder 概念WES 对应物落地含义
Quest Task harness_runs / AI 评估任务 一个 Run 承载一次文件理解、报告生成、澄清、确认和草稿交付。
Intent Router Phase 1G 意图路由 / Tool Planner 区分能力发现、业务问答、附件问答、报告生成、数据查询和写动作确认。
Source Workspace 上传文件、用户补充、项目背景、标准文件版本 当前报告生成和写动作绑定 Run，普通附件问答只保留轻量审计；RP-047 目标为任何需跨浏览器生命周期执行的 AI turn 都创建轻量 Run。
Execution Workspace Harness stage、modelRun、toolEvent、schema validation 执行状态不靠前端猜测；Harness 流程由持久状态和审计对象驱动。RP-047 将在保留轻量 modelRun 摘要的同时，增加可重连的 Run 状态与输出快照。
Artifact Workspace file_understanding、v1/v2 report、evidence、AI 草稿链接 RP-005 第一批已在 AI 工作台右侧把 session 来源、执行、产物、待确认动作和关联记录组织为运行时间线；后续继续补 Harness run 级 evidence/modelRun/toolEvent。
Delivery Workspace 传统项目/评估草稿、人工确认、正式评估入口、1F 回写审计 交付必须落到传统业务边界，且能从 Harness 反查到人工落地结果。
Knowledge Scope 用户记忆、团队规范、项目知识、仓库/标准知识、任务级引用 知识不作为全局 prompt 池，而按范围、版本、证据和启用状态进入任务。
Section 03

六个任务边界

01来源边界Run 绑定 sourceFile、用户补充、标准版本和项目背景；不连接本地目录，不开放命令执行。
02意图边界普通追问、附件问答、报告生成、WES 数据查询和写动作请求走不同路径。
03执行边界阶段机决定是否可 parse、generate v1/v2、confirm；RP-047 目标中，需后台持续的普通问答也创建轻量 Run，并保留 modelRun 摘要。
04产物边界artifact、回答、待确认动作和关联记录已在右侧时间线集中展示；evidence/modelRun 细粒度追溯后续补齐。
05交付边界AI 草稿进入传统 WES；正式业务动作必须人工确认，Phase 1F 回写 Harness 审计。
06知识边界知识按用户、团队、项目、标准、任务引用分层；回答和报告都应说明采用了哪些上下文。

Section 05

阶段安排建议

近期可做当前优先
  • Phase 1G 已交付：建立 Intent Router，拆分能力发现、业务问答、附件问答、报告生成、WES 查询和写动作确认。
  • Phase 1G 已交付：修正 v1 后普通追问自动生成 v2 的路径，卡片提交和明确报告意图才推进 v2。
  • Phase 1H 第一批已交付：Run Timeline 与 Artifact Workspace 初版，复用 AI session 数据集中展示来源、执行、产物、待确认动作和关联记录；后续补 Harness run 级证据链。
后置评审暂不进入当前范围
  • 向量库与 embedding 厂商选型后置到标准文件/知识规模清晰后。
  • Prompt Profile CRUD 后置到多角色、多客户、多模型差异稳定后。
  • 标准治理 Harness 化不挤进 1G，避免扩大当前闭环范围。
  • 不自动创建正式项目评估、正式需求或正式发布记录。
执行原则先稳定任务执行边界，再讨论更强的 AI 自主能力。否则 AI 即使能生成更多内容，用户仍无法判断应该审核哪份产物、确认哪个动作、由谁承担责任。
Section 06

监控与评测指标

意图识别

意图命中率

抽样检查业务问答、附件问答、报告生成、数据查询和写入请求是否进入正确路径。

任务边界

边界完整率

抽样检查每项任务是否有来源、阶段、任务产物、工具动作、草稿链接和负责人信息。

过程记录

追溯完整率

从传统草稿能反查 AI 任务和确认动作，也能从 AI 任务反查草稿及人工确认结果。

证据依据

证据覆盖率

报告关键结论是否有证据、来源文件、标准版本或用户补充作为依据。

用户采纳

草稿采纳率

统计报告生成后，用户选择下一步、进入草稿和完成人工确认的比例。

人工调整

人工修改量

统计 AI 草稿被人工编辑的幅度，用于判断报告是否贴近真实评估口径。

处理效率

Token 与轮次

知识范围生效后，应减少无效输入、重复追问和人工补充轮次。
