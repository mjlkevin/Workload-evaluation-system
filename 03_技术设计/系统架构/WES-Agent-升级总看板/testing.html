Section 01

测试策略

人工测试不重复自动化测试的断言，而是验证真实用户在浏览器中能否完成从 AI 工作台到传统草稿处理的业务闭环，并确认边界提示足够清楚：AI 只生成草稿，正式业务仍由人确认。

P0主链路任务
6
上传 / v2 / confirm / 草稿追溯
P1边界任务
4
权限 / fallback / 不自动正式化
P2巡检任务
2
刷新持久化 / 看板链接
R当前结果
0/12
待人工执行并回填
准备

测试数据

使用 1 份真实或脱敏的需求附件，包含项目背景、需求清单和至少一个需用户补充的信息缺口。

环境

执行环境

使用本地或集成环境的 ui/V2_PROTOTYPE 与 apps/api，以普通用户登录验证 owner 边界。

证据

反馈证据

每条失败或疑问都需要记录页面、操作步骤、实际结果、截图路径和建议处理优先级。

Section 05

缺陷分级

等级判定标准处理要求
P0 主链路不可用、权限泄露、重复创建草稿、自动进入正式评估、Harness 追溯丢失。 阻断发布或阶段完成声明，必须修复并重测。
P1 跳转错误、状态提示误导、fallback 可点击、刷新后部分信息缺失。 进入本轮修复或明确延期决策，不能静默忽略。
P2 文案、样式、布局、文档链接等不影响主链路和边界判断的问题。 进入后续优化池，按影响面排序处理。
Section 06

关闭标准

人工测试关闭条件所有 P0 用例必须 Pass；P1 用例必须 Pass 或有明确延期决策；所有失败、阻断和豁免都需要在本页、风险页或变更页留下可追溯记录。
Must Pass

P0 全部通过

上传、v2、confirm、AI 草稿列表、详情来源追溯不能失败。

Decision

P1 有处理结论

权限、fallback、跳转、正式化边界出现问题时必须明确修复或延期。

Trace

证据可追溯

人工测试结果需要能反向定位到任务 ID、页面、截图和变更记录。
