RP-017 · AI 工作台切换后会话丢失

用户在 AI 工作台发起对话后，切换侧边栏导航或 AI/传统工作台 toggle 再返回，对话会话与消息全部丢失。后端会话持久化逻辑正确，问题在前端恢复链路。

问题

AiHomeWorkbench 卸载后 state 全部清零

组件卸载时 sessions、activeSession、messages 全部丢失。重载时 loadSessions() 虽从后端拉回会话列表，但 setActiveSession((current) => current || items[0] || null) 总是回退到 items[0]，无法记住卸载前的活跃会话。

影响

用户体验断裂

用户每次切换导航后返回 AI 工作台，都看到空白会话列表或错误的会话，需要重新发起对话。高频操作场景下体验极差。

边界

前端恢复链路，不涉及后端

后端 appendAiSessionEvent 已正确持久化消息到 data/ai-sessions.json。修复范围限定在 useAiSessions hook 与 AiHomeWorkbench 组件。

验收口径用户在 AI 工作台发送消息 → 切换侧边栏到"需求" → 切回"AI 工作台" → 原会话与消息完整恢复。切换 AI/传统工作台 toggle 同理。若 loadSessions API 失败，用户看到错误提示而非空白页面。

人在环落地

  • 交付物：行业背景摘要、客户画像、需求-模块映射、问题清单回复、待确认问题、实施评估输入建议。
业务价值why
  • 降低售前顾问从材料到客户回复的准备时间。
  • 把制造业方法论、金蝶产品模块经验和 WES 评估口径沉淀为可复用资产。
  • 让 AI 输出具备证据、假设和待确认问题，避免“看起来专业但不可复核”。
  • 为后续行业 Skill、客户专项 Skill、售前知识包和需求包生成打基础。
