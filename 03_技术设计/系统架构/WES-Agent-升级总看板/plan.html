Section 04

Phase 1F 目标

交付口径当用户在传统工作台对 AI 草稿执行人工确认时，系统把这次人工动作回写到对应 Harness run/action 的审计链中，形成从 AI 建议到人工落地的闭环证据；正式发布仍走传统版本/评估流程。
Audit

回写审计

记录确认人、确认时间、草稿 ID、ToolEvent ID、状态变化和回写结果。

Boundary

权限边界

只允许 owner 或具备权限的用户触发回写，不绕过 JWT、owner 和传统版本流程。

UX

可见反馈

传统详情页展示回写状态，让用户知道草稿已被人工处理并纳入 Harness 审计。

Section 08

暂不进入范围

范围原因触发条件
向量库Phase 1D/1E 的核心问题是草稿确认链路，不是检索增强。出现稳定的多文档跨项目检索需求后再评估。
Prompt Profile CRUD当前模型行为先通过固定 schema 和 Harness 阶段约束收敛。多角色、多客户提示词差异稳定后再产品化。
标准治理 Harness 化会扩大业务范围，冲淡草稿闭环。传统草稿闭环稳定后单独立项。
自动创建正式评估违反人在环确认边界。必须另行评审权限、审计和撤销机制。
