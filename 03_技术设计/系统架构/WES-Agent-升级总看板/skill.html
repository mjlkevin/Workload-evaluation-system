wes-multi-agent-collaboration

多 Agent 协作协议是 WES 系统的核心枢纽 Skill，负责协调 Codex、Qoder 等 AI Agent 之间的工作分配与协作（KIMICODE 已于 2026-08-09 退出，NightOps 已下线）。

核心职责

  • 任务分类与 Agent 分配
  • 结构化 Handoff 与验收/返工/拒收
  • Agent 注册表管理
  • 冲突与权责规则

触发条件

  • 跨 Agent 任务协调
  • 外部 AI Handoff 审查
  • 新 Agent onboarding

Section 03

层级说明与治理边界

Layer 1

核心协作层

wes-multi-agent-collaboration、wes-qoder-worktree-protocol、speak-plainly：负责任务分配、Worktree 隔离执行与结构化验收，并统一任务沟通表达规范。

Layer 2

治理看板层

maintain-wes-command-board、recording-wes-requirements：关键过程事实沉淀到总看板，反馈先入问题池再分诊处置，避免重复建项。

Layer 3

质量保障层

wes-security-review、wes-code-review、wes-tdd：安全审查、五轴代码审查与测试驱动开发构成合并前的三道质量门禁。

Layer 4

前端专用层

improving-wes-ui：仅限 ui/V2_PROTOTYPE 主线，单次限定一个业务表面与最多三个已证实根问题，未经独立架构决策不引入新 UI 技术栈。

External

外部插件

fireworks-tech-graph：负责生成 SVG/HTML 技术图表等视觉资产，本页架构图即由其产出。ui-skills：UI 技能集与路由层（improve-ui、fixing-accessibility 等 6 个子技能），由 npx ui-skills start 唤起，是 improving-wes-ui 门禁的强制前置，仅提供技能上下文与审计规则，不替代项目内 WES Skill 决策。【已移除】i-have-adhd：其 ADHD 友好输出塑形规则已于 2026-08-09 合并入 speak-plainly（Shape for Action 章节）随日常汇报自动生效，插件本体已删除。

治理边界Skill 调用遵循 AGENTS.md 约束：治理类 Skill 是对应任务的强制前置，质量类 Skill 按门禁顺序串行执行，外部插件（图表生成、UI 技能路由）仅辅助产出，不参与业务决策；输出塑形能力已内化为 speak-plainly 的日常规则。
