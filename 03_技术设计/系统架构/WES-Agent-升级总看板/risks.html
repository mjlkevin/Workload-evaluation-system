Section 03

架构边界

必须守住底线规则
  • AI 任务运行与审计底座（Harness）可以创建草稿和待确认动作。
  • 传统业务正式落库必须有明确人工确认链路。
  • 所有写动作都要留下可复核的关键动作记录（ToolEvent）。
  • 不得绕过登录鉴权，也不得查看或操作其他用户的数据。
  • AI 任务域使用 PostgreSQL；其他传统业务未满足迁移条件前，不改变现有主存储。
本阶段暂不扩大范围控制
  • 不引入向量库。
  • 不引入 Prompt Profile CRUD。
  • 不把标准治理流程 Harness 化。
  • 不自动创建正式项目评估或正式需求记录。
  • 不恢复已删除或下线的第二前端主实现。
Section 04

关键决策

决策结论原因
产品形态L2 内嵌 Copilot，而非 L3 全自主 Agent。WES 的价值是规则驱动、可控、可追溯；写动作需要人在环。
前端主线ui/V2_PROTOTYPE 是唯一 Web 主线。Agent 工作台和后续体验都在 V2 演进。
后端主线apps/api 是唯一服务入口。继续沿 modules/routes 模式扩展。
Harness 存储Harness 作为首个 PostgreSQL-backed 新业务域。审计、统计、权限追溯与模型回放需求已触发 DB 迁移条件。
Phase 1D confirm只创建传统草稿，不创建正式评估。保留传统系统人工确认和版本流程。
v1 nextActions保持 disabled。v1 只是初步报告，不能引导正式动作。
v2 fallback nextActions没有真实 nextActions 时按钮 disabled。避免用兜底按钮制造不可追溯动作。
legacy report标记为历史产物，非 Harness 生成。避免新旧报告混淆。
输入方式上传文件为主，不做本地路径连接器和命令执行。降低权限、数据泄露和不可审计文件操作风险。
标准文件原始附件文件存储，DB 保存元数据、解析结果和 evidence。官方标准频繁升版，不适合过早字段级内置。
模型职责文件业务理解必须真实调用 LLM。代码抽取只负责证据整理，不能代替业务理解和风险判断。
formBlock 交互协议结构化表单必须先经过后端白名单校验，再由前端渲染；提交仍是普通用户 chat 消息。后端协议、session metadata 与前端 InteractiveFormCard 已实现；提交复用 sendMessage(messageOverride)，避免 LLM 直接驱动写动作。
低置信度粗评规则缺失时允许生成低置信度粗评，并生成待补标准动作。不阻断内部讨论，但必须暴露假设和依据缺口。

Section 07

决策触发器

以下条件出现时，应该先更新设计/计划/风险页，再实施对应技术迁移或范围扩大。

DB Migration

传统域数据库迁移

出现高频并发写冲突、核心查询 P95 超阈值、多实例部署需求，或审计/统计/权限追溯显著增加。

Agent Autonomy

提高 Agent 自主级别

只有当草稿确认链路稳定、撤销机制清楚、审计覆盖完整后，才考虑从 L2 向更强自治演进。
