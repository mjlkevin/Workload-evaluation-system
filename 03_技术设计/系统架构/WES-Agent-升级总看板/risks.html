Section 03

架构边界

必须守住底线规则
  • AI 任务运行与审计底座（Harness）可以创建草稿和待确认动作。
  • 传统业务正式落库必须有明确人工确认链路。
  • 所有写动作都要留下可复核的关键动作记录（ToolEvent）。
  • 不得绕过登录鉴权，也不得查看或操作其他用户的数据。
  • AI 任务域使用 PostgreSQL；其他传统业务未满足迁移条件前，不改变现有主存储。
本阶段暂不扩大范围控制
  • 不引入向量库。
  • 不引入三元组库与 OWL 推理机（RP-059 只取本体建模方法，载体为 PG 表 + 现有 DSL 引擎）。
  • 不引入 Prompt Profile CRUD。
  • 不把标准治理流程 Harness 化。
  • 不自动创建正式项目评估或正式需求记录。
  • 不恢复已删除或下线的第二前端主实现。

本体融合边界（RP-059）取本体的建模方法（概念、继承、一致性检查），不引 OWL 推理机与三元组库；概念数据落 PG 普通表，规则仍由现有 DSL 引擎执行。OWL 语义与评估场景相反、不做算术，且阶段 2 正把 9 个 store 收敛到 PG。
三条硬约束① OWL 是开放世界 + 单调推理，与「未填写即缺失」「调研后撤销结论」的评估语义相反，缺失校验仍需闭世界的 DSL 规则；② OWL 不做算术，initial-estimate.ts:68 的 (10+n×3)×行业系数 必须留在计算引擎；③ 此时新增存储引擎会重造跨存储非原子写债务。
Electron 桌面端定位（RP-051）桌面端定位为连接共享服务器的客户端，不做单机离线；数据库留在服务器端部署（应用与数据库分离），桌面端不内嵌任何数据库。用户 2026-08-06 拍板；该定位同时消除内嵌 PG 与本地数据目录两大障碍，桌面范围收敛为客户端壳；前置条件是服务器端需部署 V2 前端静态托管（当前 docker-compose 无 web 服务）。
