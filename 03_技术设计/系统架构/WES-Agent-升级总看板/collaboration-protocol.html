Section 01

核心判断

当前 WES + Codex + Qoder + KIMICODE 的跨工具协作，本质上是一套“协议先本地化”的 Agent-to-Agent 工作约定：用 Git 保存执行状态，用固定 handoff 承载交付事实，用总看板沉淀共享项目记忆，用可复跑验证命令替代口头完成声明。Codex 是规划指挥与审计 Gate，Qoder 是高吞吐执行者，KIMICODE 进入 NightOps peer audit pilot；Claude Code 或后续 Agent 在完成注册、ACK、试运行和复核前仍只能处于候选状态。

State

Git 是状态载体

每个 RP 或工作单对应独立 worktree、branch、baseCommit 和 commit。状态不靠聊天上下文记忆，而靠可检查的版本对象。

Contract

Handoff 是交付协议

执行 Agent 输出目标、Worktree、文件清单、验证命令、风险、看板建议和下一步。缺字段时 Codex 可拒收。

Authority

状态权责分离

执行 Agent 只能报告“已回填 / 待 Codex 复核”；Codex 做复核和必要修复；用户保留最终验收与是否集成的判断。

Section 03

五层协议

任务层用户、需求池或计划页定义目标、范围和优先级；Codex 不在本项目中创建持续 Loop，当前由 Qoder 负责 Loop 执行。
隔离层执行 Agent 每个 RP 使用独立 worktree 和专属 branch prefix；Codex 修复使用 codex/* branch；主 checkout dirty 变更不得被清理或混入。
交付层handoff 必须包含 Worktree、变更文件、验证命令与结果、风险、看板同步建议和下一步。没有证据不接受“已完成”。
复核层Codex 对照声明文件查 diff，复跑相关命令，检查权限、owner 隔离、API 契约、前端主线和无关变更。
沉淀层可接受事实同步到总看板；需求状态、验证结果、风险和变更记录在页面之间保持一致。

Section 05

多 Agent 协作机制

Registry Fields

每个 Agent 都要登记

  • agentId、平台、启用状态。
  • 角色槽位：owner、planner、executor、reviewer、integrator、board-steward。
  • allowedScopes、forbiddenScopes、branchPrefix。
  • handoffProfile、verificationProfile、boardSync 责任。
  • onboardingAck 与试运行记录。
Assignment Gate

任务分派前置门禁

  • 只有 active Agent 可以承接正式任务。
  • 并行任务必须文件范围独立、验证命令独立、worktree 独立。
  • 执行 Agent 不拥有“已交付”状态权。
  • 新 Agent 的第一轮只能做非关键试运行或只读复核。
  • 任何 Agent 不得绕过密钥、权限、owner 隔离和人工确认规则。
协作模式使用场景控制点失败时处理
顺序 handoff 一个 Agent 完成实现，另一个 Agent 复核或集成。 先完整 handoff，再开始 review。 缺字段或缺验证时退回返工。
并行 worktree 多个 RP 文件范围独立，可同时推进。 一任务一 worktree / branch / baseCommit。 发现共享文件冲突时暂停其中一项。
复核升级 存在权限、API 契约、数据隔离、测试缺口或范围叠加。 Codex 记录阻断原因并生成返工提示词。 不得通过看板直接标记已交付。
集成队列 多条已验证 patch 等待进入主线。 按 RP 提取最小 patch，逐条合并逐条验证。 任一项失败时只回滚该项，不扩大范围。
看板治理 只改变协作规则、事实源、计划或流程资产。 更新 sources / changes / collaboration protocol。 不得伪造成代码交付。
扩展原则新增 Agent 时只新增注册表条目、入口文件、handoff profile 与试运行记录；不重写现有协议，也不把工具品牌直接等同于权限。
Section 06

NightOps 无人值守机制

NightOps 用于北京时间 00:00-09:30 的无人值守窗口。Codex 负责发布任务包、限定范围和最终审计 Gate；Qoder 默认作为主执行者；KIMICODE 作为交叉审计者或受控小修槽位。该机制只允许推进“已回填 / 待复核”或“返工完成 / 待 Gate”状态，不允许无人值守标记“已交付”、合并主线或处理需要用户裁决的架构事项。共享模板见 docs/agent-loop/nightops-templates.md。

Commander

Codex 发布任务包

在固定时间点生成 Night Mission Packet，定义任务、执行者、审计者、allowedPaths、stopConditions、验证命令和 handoff/audit 路径。

Executor

Qoder 主执行

读取任务包和上一轮 Codex Gate，按一任务一 worktree 实现、测试并输出 handoff；如存在返工指令，先返工再谈新任务。

Peer Audit

KIMICODE 交叉审计

检查范围污染、权限边界、测试缺口、架构风险和 handoff 完整性；必要时只做受控小修，不替代 Codex 最终 Gate。

时间段（北京时间）负责方动作输出物硬限制
23:40-23:55 Codex 发布 Night Mission Packet，选择 1 条低风险 RP 或返工任务。 docs/agent-loop/nightly/YYYY-MM-DD-mission.md 不启动实现；只做规划、边界和门禁。
00:00-03:30 Qoder 按任务包执行，创建隔离 worktree，完成实现和自测。 Qoder handoff + branch / worktree / verification evidence 最多推进到“已回填 / 待 Codex 复核”。
04:00-05:30 KIMICODE 审计 Qoder handoff、diff 范围、验证命令、权限和架构边界。 KIMICODE peer audit 不得宣布交付；发现硬边界问题必须要求停止。
05:30-07:00 Qoder 若 peer audit 要求返工，先修当前任务；不得拿新需求。 rework handoff 无 Codex allowNextTask=true 不进入下一 RP。
07:00-08:00 KIMICODE 复核返工结果，标注剩余风险和建议结论。 peer re-audit 仍不能替代 Codex Gate。
08:00-09:00 Codex 执行 Audit Gate，复核 Qoder + KIMICODE 证据，给出结论。 Codex Gate Result 审计 Gate 不是需求池实现 Loop，不自动写新需求代码。

Section 08

角色与权限槽位

槽位能做什么不能做什么当前承担者关键输出
Owner / Acceptor 设定目标、优先级、最终验收口径；决定是否启动 Qoder Loop 或让 Codex 一次性执行。 不需要直接维护内部状态文件。 用户 任务目标、验收反馈、是否继续下一项。
Planner / Commander 发布任务包、设置执行/审计角色、限定路径、设置 Gate 结论和下一步。 不得在无人值守窗口自行实现新需求；不得跳过用户最终验收。 Codex Night Mission Packet、Codex Gate Result、晨间简报。
Executor 在隔离 worktree 中实现、测试、提交结构化 handoff。 不得编辑 main checkout；不得宣告“已交付”；不得改无关文件或泄露密钥。 Qoder1；KIMICODE 可在专项任务中候选 Worktree Contract ACK、commit、handoff。
Peer Auditor 交叉审计执行结果、验证证据、范围污染、权限和架构边界。 不得替代 Codex Gate；不得标记已交付；不得扩大返工范围。 KIMICODE pilot；Codex 兜底 peer audit、finding、返工建议。
Reviewer / Fixer 复核 Qoder 交付、跑验证、补最小修复、同步总看板、给出合并建议。 不得创建 WES 持续 Loop；不得还原用户或其他工具的无关 dirty changes。 Codex；KIMICODE / Claude Code 候选 复核结论、修复分支、验证证据、看板同步。
Integrator 提取最小 patch、给出合并顺序、验证集成后状态。 不得整分支粗暴合并，不得带入运行态数据。 Codex / 用户授权 最小 patch、验证记录、集成建议。
Board steward 承载跨工具共享项目事实、风险、计划、验证、变更和需求状态。 不替代代码、测试和人工验收；不得保存密钥或临时日志。 Codex 维护；总看板承载 requirements / plan / testing / monitoring / risks / changes / sources。
Section 09

交付包与拒收条件

Required Handoff

每轮必须包含

  • 目标和边界。
  • projectRoot、worktreePath、branch、baseCommit、taskId。
  • 逐文件变更清单。
  • 验证命令、pass/fail/not run 和关键输出。
  • 风险、未验证项、看板同步建议和下一步。
Reject Conditions

Codex 应退回

  • 没有 worktree、branch、baseCommit。
  • 没有文件清单或验证命令证据。
  • 混入无关 dirty changes、运行态数据、历史主线路径。
  • 绕过 JWT、owner 隔离、人工确认或 dispatch 边界。
  • 泄露 API Key、token、cookie、私钥。
