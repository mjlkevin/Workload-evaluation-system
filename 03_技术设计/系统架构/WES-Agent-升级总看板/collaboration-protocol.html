Section 01

核心判断

这套规则的核心很简单：任务先分清责任和范围，执行过程彼此隔离，交付时必须带证据，复核通过后才能推进。Codex 负责任务规划和最终复核，Qoder 负责主要实施；KIMICODE 已于 2026-08-09 退出项目，Claude Code 不参与本项目开发；其他 AI 在完成规则确认、试运行和复核前，不能独立承担正式任务。

过程状态

用 Git 保存可核对的进展

每项需求对应独立开发目录、分支、起点提交和结果提交。进展不依赖聊天记忆，而是可以直接检查。

交付清单

交接必须带完整证据

执行方需要说明目标、开发目录、改动文件、验证结果、风险、看板建议和下一步；信息不全时可以拒收。

决定权限

执行、复核、验收相互分开

执行方只能报告“已回填 / 待 Codex 复核”；Codex 负责复核和必要修复；用户决定最终是否接受和集成。

Section 03

五层协议

任务层用户、需求池或计划页定义目标、范围和优先级；Codex 不创建持续实施流程，定期执行由 Qoder 负责。
隔离层执行方每项需求使用独立开发目录和专属分支；Codex 修复使用 codex/* 分支；主目录中已有的未提交修改不得被清理或混入。
交付层交接必须包含开发目录、变更文件、验证命令与结果、风险、看板同步建议和下一步。没有证据，不接受“已完成”。
复核层Codex 对照交付清单检查实际差异，复跑相关命令，并检查权限、用户数据隔离、接口约定、前端主线和无关变更。
沉淀层可接受事实同步到总看板；需求状态、验证结果、风险和变更记录在页面之间保持一致。

Section 05

多 Agent 协作机制

Registry Fields

每个 Agent 都要登记

  • agentId、平台、启用状态。
  • 角色槽位：owner、planner、executor、reviewer、integrator、board-steward。
  • allowedScopes、forbiddenScopes、branchPrefix。
  • handoffProfile、verificationProfile、boardSync 责任。
  • onboardingAck 与试运行记录。
Assignment 关卡

任务分派前置门禁

  • 只有 active Agent 可以承接正式任务。
  • 并行任务必须文件范围独立、验证命令独立、worktree 独立。
  • 执行 Agent 不拥有“已交付”状态权。
  • 新 Agent 的第一轮只能做非关键试运行或只读复核。
  • 任何 Agent 不得绕过密钥、权限、owner 隔离和人工确认规则。
  • CLI 直驱通道前置规矩 · 凭据不进对话：API Key、token、cookie、私钥不得进入对话、提示词、看板或提交。
  • CLI 直驱通道前置规矩 · 模型显式选型：机械性、低判断量任务必须显式指定廉价模型，不沿用默认档位。
协作模式使用场景控制点失败时处理
顺序 handoff 一个 Agent 完成实现，另一个 Agent 复核或集成。 先完整 handoff，再开始 review。 缺字段或缺验证时退回返工。
并行 worktree 多个 RP 文件范围独立，可同时推进。 一任务一 worktree / branch / baseCommit。 发现共享文件冲突时暂停其中一项。
复核升级 存在权限、API 契约、数据隔离、测试缺口或范围叠加。 Codex 记录阻断原因并生成返工提示词。 不得通过看板直接标记已交付。
集成队列 多条已验证 patch 等待进入主线。 按 RP 提取最小 patch，逐条合并逐条验证。 任一项失败时只回滚该项，不扩大范围。
看板治理 只改变协作规则、事实源、计划或流程资产。 更新 sources / changes / collaboration protocol。 不得伪造成代码交付。
分支每日对齐 分支存活超过一天，或与其他线改到同一批文件。 每天 git fetch origin && git pull --rebase origin main 对齐；冲突按「三轴并存」解，不改写已推送历史。 确实无法并存时停下报架构侧，不得由执行方自行取舍。
写操作归属登记 FF 合入、分支删除、worktree 注销、吸收看板草稿等改变共享状态的操作。 只登记可核实事实：时刻、sha、操作类型、否认记录。

NightOps 无人值守机制（已下线）

【历史说明，已下线】NightOps 无人值守三 AI 协作机制已于 2026-08-09 整体下线：模板 nightops-templates.md、mission/brief/TRIAL 产物与 KIMICODE peer audit Loop 脚本均已删除，KIMICODE 同步退出项目。本节以下内容为历史记录，禁止据此重建无人值守 Loop；如需恢复夜间自动化，须经用户重新授权并重建协议。

（历史机制说明）NightOps 曾是北京时间 00:00-09:30 的夜间协作窗口：Codex 先发布任务包并限定范围，Qoder 实施，KIMICODE 做交叉检查，最后由 Codex 复核。夜间最多推进到“已回填 / 待复核”或“返工完成 / 待复核”，不能自行标记已交付、合并主线，也不能处理需要用户决定的架构事项。

Commander

Codex 发布任务包

在固定时间点生成 Night Mission Packet，定义任务、执行者、审计者、allowedPaths、stopConditions、验证命令和 handoff/audit 路径。

Executor

Qoder 主执行

读取任务包和上一轮 Codex 关卡，按一任务一 worktree 实现、测试并输出 handoff；如存在返工指令，先返工再谈新任务。

Peer Audit

KIMICODE 交叉审计

检查范围污染、权限边界、测试缺口、架构风险和 handoff 完整性；必要时只做受控小修，不替代 Codex 最终 关卡。
