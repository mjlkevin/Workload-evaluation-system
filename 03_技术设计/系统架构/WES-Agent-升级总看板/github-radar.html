Section 01

模块定位与收录口径

项目每天通过定时任务搜寻 GitHub 上与 WES 相关的开源项目。搜寻结果如果只留在对话或日报里，很快就会丢失。本页把其中真正有启发性的工具沉淀下来：每个工具都要对照 WES 当前代码做结合点论证，说明它能改进哪个模块、怎么落地、风险是什么，作为后续架构优化迭代的候选基础。

入口

定时任务产出

每日 GitHub 雷达按“搜寻 → 核验 → 分析 → 报告”运行；本页只收录通过核验且与 WES 有具体结合点的工具，其余候选留在日报中。

论证

代码级结合点

每条结合点必须指向仓库内真实存在的模块、文件或命令（如 modules/trace、test:ai、data/traces），不接受泛泛的“可能有价值”。

边界

收录不等于引入

收录只是沉淀候选。实际引入必须遵守 AGENTS.md 的架构边界：不引入第二前后端主实现、满足 DB 迁移触发器才接入数据库、密钥不进文档与看板。

三维评级口径启发性 = 方法论/模型对 WES 思路的启发程度；优化价值 = 对现有模块质量、效率、可观测性的直接改进空间；架构改进 = 对未来架构演进方向的影响深度。五星为上限。

Section 03

GT-001 · DeepEval（confident-ai/deepeval）

类 Pytest 的 LLM 单元测试框架，内置 G-Eval（LLM-as-a-judge）、Answer Relevancy、Hallucination、JSON Correctness、Task Completion 等 40+ 指标，支持任意 LLM 作为裁判模型。对 WES 的直接意义是：AI 评估输出（工作量估算、售前简报、销售简报）第一次有了可参照的“输出质量回归”方法论。

核心价值

把 LLM 输出变成可断言对象

像写单元测试一样校验模型输出：JSON 结构正确性、答案相关性、幻觉检测、任务完成度，并支持固定数据集回归。

许可与栈

Apache-2.0 · Python

许可友好；但与 WES 的 Node/TypeScript 主栈异构，完整框架引入需要独立 CI 步骤，不建议侵入主栈。

成本约束

LLM-as-judge 消耗 token

裁判模型调用有真实成本，只应在关键回归集启用，不进入每次提交的默认测试。

与 WES 的结合点论证（2026-08-04 代码核验）已核实
结合点仓库现状（已核验事实）DeepEval 带来的改进
npm run test:ai apps/api/package.json 的 test:ai 用 tsx --test 运行约 20 个测试文件（extractor、presales、sales-briefing、dev-assessment、change-management、dsl rules、rbac 等），全部为确定性功能断言；另有 test:ai:cc Testcontainers 变体。当前没有针对真实模型输出质量的回归线。 对标其指标体系补一条“输出质量回归”：固定样本输入（SOW/需求文档）→ 校验输出 JSON 结构、字段完整性、结论稳定性；并可覆盖提示词漂移（prompt drifting）场景。
结构化输出契约 apps/api/src/ai/contracts/（wes-contracts.ts、structured-output.ts 及配套测试）已对 AI 结构化输出做 schema 级校验。 JSON Correctness 方法论可把现有校验从“结构能解析”升级为“字段语义完整 + 关键结论稳定”，在契约层建立质量基线。
规则引擎回归 config/rules/example-rule-set.json 带 ruleVersion / pipelineVersion 版本化；scripts/rule-regression-check.js（rules:regression）守护确定性管线。 规则配置调整后，确定性管线已有回归，但 LLM 参与环节（抽取器、AI 兜底路由）的输出质量目前无监控——这是 DeepEval 思路最直接的补位点。
评估核心 modules/ai 为 facade，实际实现在 services/ai（assessment、extractor、workbench-dispatch 等）；产出工作量评估、售前简报、销售简报、开发评估等。 为每类评估产物建立固定样本基线 + 指标断言，防止模型升级或提示词调整导致质量无声退化。
实施建议第一步仅借鉴指标方法论：用 TypeScript 在 test:ai 中实现轻量版（G-Eval 评分标准 + JSON Correctness 断言），零依赖引入；若后续需要完整框架，在 CI 以独立 Python 步骤运行，不侵入 Node 主栈。前置条件是建立固定样本基线（可复用 docs/ 下 SOW 标准版样本）。
风险① LLM-as-judge 有 token 成本，只对关键回归集启用；② Python 生态与 Node 主栈异构，完整引入需权衡维护成本；③ 质量基线本身需要人工标定期望值，初期投入不可省略。
Section 04

GT-002 · Langfuse（langfuse/langfuse）

开源 LLM 工程平台：调用链路追踪（tracing）、Prompt 版本管理、评估数据集、Playground、LLM-as-judge 评估一体，提供 TS SDK 与 OpenAPI，docker compose 自托管。对 WES 的直接意义是：自研 trace / 会话 JSON 结构演进到平台级可观测性时，它是成熟参照系。

核心价值

trace/span + Prompt 版本管理

统一的调用链模型、Prompt 版本与缓存、评估数据集和回放能力，覆盖 AI 可观测性的完整生命周期。

许可与栈

TypeScript · MIT 核心

核心 MIT 许可、TS 技术栈与 WES 同构；但企业版（EE）条款有边界，自托管需确认使用范围落在核心许可内。

部署重量

ClickHouse / Postgres / Redis

完整自托管组件栈较重，已并入 ClickHouse 团队。按 AGENTS.md DB 迁移触发器原则，当前应“借鉴数据模型”而非全量引入。

与 WES 的结合点论证（2026-08-04 代码核验）已核实 · 含一处口径修正
结合点仓库现状（已核验事实）Langfuse 带来的改进 / 参照
统一 Trace 模型 RP-030 已在 apps/api/src/modules/trace/trace.types.ts 定义 TraceRecord / TraceSpanData：8 类 span（intent_routing、knowledge_retrieval、model_call、tool_call、artifact_generation、user_confirmation、write_action、degradation），含 tokenUsage、modelInfo 与 redactSensitiveFields 脱敏。 WES 自研模型与 Langfuse trace/span 结构同构，方向正确；差距在平台能力（可视化、评估数据集、回放）。可将 Langfuse 作为该模型演进的对标基准。
trace 存储瓶颈 trace repository 当前为 JSON 文件存储（data/traces/trace-store.json，WES_TRACE_STORE_PATH 可覆盖）；PostgreSQL 的 traces 表已在 apps/api/src/db/schema/json_runtime.ts 定义。 随 Harness 审计/统计增长，先按 DB 迁移触发器把 trace 迁入已定义的 PostgreSQL 表；之后若需要平台级查询与回放，再评估 Langfuse 自托管承接，避免一步跳到重组件栈。
会话持久化 data/ai-sessions.json 以 messages + metadata（modelRun / knowledgeTool）记录会话，随使用量单文件持续增长。 与 trace 同理：短期保持文件 + 备份定位，中期参照 Langfuse 的 observation 分层把会话观测与业务消息解耦。
Prompt 版本管理 口径修正：config/templates 实为 Excel 导入层级模板，不是提示词模板；真正的提示词资产是 config/rag/prompts.json，且 knowledge span 已记录 prompt { id, version, hash }。 Langfuse 的 Prompt 版本管理 + 缓存机制，是 WES 提示词 id/version/hash 机制下一步演进（发布流程、灰度、效果对比）的直接参照。
Harness 域 Harness 已是 DB-backed（PostgreSQL），审计对象为 run / artifact / modelRun / toolEvent。 若未来需要模型回放与统计，可评估以 Langfuse 自托管实例承接 AI 可观测性部分；必须满足 DB 迁移触发器并遵守脱敏红线（API Key / token 不进 trace）。
实施建议短期：借鉴数据模型，输出 WES trace/span 与 Langfuse observation 的映射表；本地 docker compose up 试跑，将 services/ai 的一次 Kimi 调用接入 TS SDK 做 PoC，对比自研 trace 的信息完整度。中期：若 PoC 通过，把 AI 会话观测迁入 Langfuse，data/ai-sessions.json 降级为备份。
风险① ClickHouse / Postgres / Redis 组件较重，须先满足 AGENTS.md DB 迁移触发器再考虑全量引入；② 注意 EE 条款边界，自托管前确认所需功能均在 MIT 核心范围；③ Langfuse 接入后仍须执行与自研 trace 相同的脱敏策略，密钥与敏感原文不得进入观测数据。
